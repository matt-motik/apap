# Процесс работы (workflow) v1.0

**Префикс:** `WF1.0` (реестр префиксов — в шапке `ROADMAP.md`; задачи процесса — `WF1.0-B<N>` в Баг-раунде).

Спецификация процесса: правила работы агента и пользователя с репозиторием (`AGENTS.md`, `_STATE_.yaml`, `ROADMAP.md`, `docs/`, хуки и `tools/`). Ядро правил — `AGENTS.md`; процедуры, которые нужны не в каждой сессии, — файлы этой папки (читаются по ссылке из `AGENTS.md`, когда до них доходит дело).

## 1. Назначение

- Единый источник правил для Claude Code и opencode: `AGENTS.md` (opencode читает его напрямую, `CLAUDE.md` только подключает его).
- Состояние между машинами переносится только через git: `_STATE_.yaml`, `ROADMAP.md`, `docs/`. Память агента и задачи сессии не переносятся.
- Форматы, которые проверяют инструменты, не меняются без отдельного решения: схема `_STATE_.yaml` (`tools/state_tool.py`), маркеры и ID `ROADMAP.md` (`tools/traceability_tool.py`), вайтлист (pre-commit), пакеты приёмки (`tools/acceptance.py`).

## 2. Решения пользователя (2026-10-22)

1. **Любая правка регистрируется.** Лёгкого пути без регистрации нет: опечатка, константа, однострочный баг, правка конфига или процесса — строка `<Префикс>-B<N>` в `ROADMAP.md` и сессия в `_STATE_.yaml` (для мелочи — один шаг). Таблица «Микро-фиксы (ручные, без сессии)» в `ROADMAP.md` остаётся историей и не пополняется.
2. **Два пути для задачи из чата:**
   - укладывается в действующие спеки → B-строка → сессия → шаги → закрытие;
   - большое (новое поведение, которого нет в спеке; несколько этапов) или противоречащее смыслу требований → агент останавливается и предлагает полный цикл (промт → ревью → ТЗ → спека, `docs/_template/process.md`); кода нет, пока спека не утверждена.
3. **Текст, закреплённый в документации.** Перед правкой текста, константы или имени агент ищет значение в `docs/` (без `_canceled/`). Если оно записано в действующей спеке или ТЗ, просьба пользователя изменить его — разрешение на правку именно этого места: агент сообщает, где закреплено, и меняет спеку и код одним коммитом. Если правка задевает смысл требования, а не формулировку, — СТОП и вопрос пользователю.
4. **Процессный префикс `WF1.0`** для правок вне спек продукта (`AGENTS.md`, `.claude/`, хуки, `tools/`); якорь — этот файл.
5. **Раздел «Стиль кода» `AGENTS.md`:** удалить устаревшие абзацы Bit-perfect/Mixed (их заменяют ADR-04, ТЗ-8 `docs/01_audio_modes_v1.0/`) и общие слова о SOLID; правило ошибок привести к линтеру (`unwrap`/`expect` запрещены вне тестов — `Cargo.toml [lints.clippy]`, ТЗ-101); жёсткие правила кода — коротким списком с указанием, какой инструмент их проверяет.
6. **`AGENTS.md` нейтрален к инструменту:** без имён агентов и механизмов конкретного клиента; правила процесса живут в репозитории, а не в памяти агента.

## 3. Состав папки

Процедурные файлы читаются по ссылке из `AGENTS.md` (раздел «Процедуры — где что читать»), когда до них доходит дело — не держать в контексте заранее:

| Файл | Когда читать | Содержание |
|---|---|---|
| `task_intake.md` | задача пришла из чата | регистрация без кода, баг vs новая фича, приоритеты, формат B-строки, закреплённый в документации текст |
| `planning.md` | старт сессии, выбор/декомпозиция задачи | режимы Продолжение/Новая задача, аудит репозитория, что читать из спеки, микро-декомпозиция, запись в `_STATE_.yaml` |
| `execution.md` | каждый микро-шаг | вайтлист, правка, верификация, успех/провал, делегирование субагентам, остановка для очистки контекста, `hooks/pre-commit` |
| `closing.md` | все шаги `[x]`, закрытие сессии/этапа | статус в ROADMAP, общие условия §8, ручные проверки, консервация `_STATE_.yaml`, итоговый отчёт |
| `architecture.md` | справочно, не при каждой сессии | проект, команды верификации, карта исходников, связка Slint↔Rust, тесты, зависимости, запуск |

`01_inventory.md` — не процедура, а учётный документ: сверка правил старого `AGENTS.md` (на коммите `b236a43`) с тем, куда каждое правило перенесено в текущей структуре, список противоречий и устаревшего. Хранится как технический паспорт решения задачи `WF1.0-B1`, не читается на каждой сессии.
