# Закрытие спецификации (WF1.0)

Применяется, когда закрыт последний этап спецификации (этап приёмки,
`closing.md` выполнен). Все пункты — один коммит
`chore(roadmap): close <Префикс>`; результаты приёмки коммитит
`tools/acceptance.py` отдельно.

1. **Открытые баги спеки.** B-строки `<Префикс>-B<N>` со статусом `⬜`/`🔄`
   покажи пользователю списком: спека закрывается, а они остаются в
   Баг-раунде со своим префиксом (ответа не жди), пока пользователь не решит иначе
   (закрыть по `closing.md`; отказаться — строка уходит в `archive_bugs.md`
   с пометкой «отклонено <дата>»).

2. **Кросс-ОС приёмка.** `python tools/acceptance.py run` по пакету спеки
   (`docs/acceptance/<name>/`, создан этапом приёмки и утверждён вместе со
   спекой) на каждой ОС пакета (Linux — десктоп, Windows — ноутбук).
   Результаты пишет и коммитит сам инструмент
   (сообщение формирует инструмент: `acceptance(<пакет>): <ОС> <вердикт> @ <hash>`) — отдельного разрешения на
   запись в `docs/` не нужно. Закрытие только когда
   `python tools/acceptance.py status` показывает прогоны всех ОС, сделанные
   после последнего этапа спеки. Вердикт FAIL — найденное оформляется
   B-строками `⬜ открыто` (`task_intake.md` §4), строка `note` — «`<Префикс>`:
   приёмка на `<ОС>` FAIL, ждёт `<ID багов>`» (прогон на старте не
   запускает), спека не закрывается до повторного прогона. Прогона
   на второй машине нет — в `note` пункта плана строка
   «`<Префикс>`: ждёт прогона приёмки на `<ОС>`» (коммит
   `chore(state): <Префикс> awaits acceptance on <ОС>`), спека не
   закрывается, работа идёт дальше по сквозному порядку. На той ОС
   `planning.md` §1 первым делом выполняет прогон, а пункты 3–5 — как
   продолжение закрытия (без отдельной B-строки `WF1.0`); строка `note`
   убирается коммитом закрытия.

3. **Архив-паспорт.** Перенеси историю этапов в
   `_TODO_/history/archive_<Префикс>.md` (например, `archive_AM1.0.md`:
   версии `vX.Y` у разных спек совпадают, уникален только префикс; прежние
   `archive_v0.x.md` не переименовываются). Запрещено слепо стирать текст —
   составь технический паспорт решения: коммиты и даты по этапам,
   применённые формулы, созданные структуры данных, размеры буферов/
   FFT-окон, зашитые Real-Time константы. Формат: заголовок, таблица
   «Этап → коммит → дата → детали», разделы «Ключевые структуры и
   константы» и «Верификация»; образец — `_TODO_/history/archive_v0.5.md`.

4. **ROADMAP.** Оставь строку глобального статуса спецификации (как
   «Спека V5.1 считается полностью выполненной» в разделе «Текущий статус
   проекта»); таблицу этапов убери — это разрешённое исключение из правила
   точечной правки `ROADMAP.md` (`known_issue` с ID её этапов — удалить,
   `closing.md` §1). Строки этапов в разделе «Сквозной
   порядок» остаются (✅), пока не закрыты все спеки этого порядка; тогда
   раздел удаляется целиком.

5. **Пункт плана.** `plan.items` → `status: done`, только когда закрыты
   все спеки, которые он ведёт; иначе — запись в `note`
   («закрыта спека <Префикс>»). Перед `done` все оставшиеся строки `note`
   переносятся в пункт «Ручные проверки за пользователем» (`closing.md`
   §2).
