## 2. Противоречия и устаревшее

1. **`expect()` разрешён vs линтер запрещает.** Старый текст («используй консервативный `expect()`») противоречит `Cargo.toml [lints.clippy]` (`expect_used = "deny"`) и `clippy.toml` (разрешение только в тестах). Касается строки №101. Решение: в ядре писать «`unwrap`/`expect`/`unreachable` запрещены вне тестов — запрещены линтером `Cargo.toml [lints.clippy]`, допускаются в `#[cfg(test)]`/`#[test]` (`clippy.toml`)», без упоминания «консервативного `expect()`» как разрешённой практики.
2. **«Порядок этапов менять запрещено» vs «сквозной порядок нескольких спецификаций».** Строка №12/44: `ROADMAP.md` фактически содержит раздел «🔀 Сквозной порядок этапов AM1.0 + SP1.0» (подтверждено чтением `ROADMAP.md`), и старый Шаг 2 п.2 уже корректно это учитывает («первую `⬜` по сквозному порядку из `ROADMAP.md`, если он задан, иначе по порядку таблицы»). Реального противоречия нет, но строка №12 в изоляции звучит как абсолютный запрет — в `planning.md` формулировать вместе («порядок внутри спецификации неизменен; порядок НЕСКОЛЬКИХ спецификаций может быть переопределён отдельным разделом сквозного порядка»).
3. **Четыре места для одного правила verification cadence.** Строки №67–68/110: правило о периодичности `cargo test`/`cargo clippy` повторено в Шаге 4 п.3 (основной текст), в «Исключении» (форматы данных/общие типы), в упоминании ЧЕКПОИНТа и в комментарии к команде `cargo test` в «Техническом контексте». Решение: единая формулировка в `execution.md` (см. №68), в `architecture.md` и ядре — просто ссылка на неё.
4. **«Пиши код полностью от начала до конца» vs точечный `patch/diff`.** Строка №65: буквальное требование переписывать файл целиком противоречит повсеместному требованию точечных правок (`ROADMAP.md` — «точечный patch/diff, не затирай соседние строки», вайтлист — минимальный необходимый набор файлов). Решение: переформулировать как «без заглушек/TODO, не удалять чужой код без прямой просьбы» (см. №65).
5. **SOLID-проза vs конкретные проверяемые правила.** Строки №97–100, 107–108: общие слова про SRP/OCP/DIP/ISP и устаревшие абзацы Bit-perfect/Mixed без проверки инструментом — убрать как общие слова (решение README §2 п.5), но сохранить две конкретные, проверяемые вещи: трейты `AudioHost`/`AudioSource` для бэкендов (подтверждено, см. №99) и инкапсуляцию состояния в `src/app/mod.rs` (требует перепроверки, см. №106 и п.6 ниже).
