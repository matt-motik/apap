# ТЗ: Визуализация аудио в плеере на Rust + Slint (v5.1)
## 1. Общие положения

### 1.1. Назначение
Добавить в музыкальный плеер (Rust + Slint) подсистему визуализации с тремя режимами, независимыми настройками для каждого и поддержкой стерео/моно.

### 1.2. Область
- Крейт/модуль: `audio::visualizer` (обработка) + `ui::visualizer` (Slint-компонент).
- Интеграция с `audio::player` (PlaybackCore, cpal callback) и `audio::decoder` (`Decoder`, `DsdDecoder`).
- UI настроек — отдельная вкладка.
- Персистентность через `serde` + TOML в `~/.config/<app>/config.toml`.

### 1.3. Термины
| Термин | Значение |
|---|---|
| Полнотрековая визуализация | Строится один раз по всему треку, кэшируется, поверх неё движется курсор |
| Мгновенная визуализация | Обновляется непрерывно во время воспроизведения |
| Кадр | Блок PCM-сэмплов / строка спектрограммы / набор полос |
| БПФ / FFT | Быстрое преобразование Фурье |
| Полоса | Частотный бин анализатора спектра |
| Tap | Копия PCM-потока, ответвляемая до записи в устройство вывода |
| Bit-perfect | Режим вывода без ресемплинга и софтверной громкости |
| Native DSD | Вывод 1-битного DSD-потока на ЦАП напрямую |
| DoP | DSD over PCM: DSD-биты в PCM-контейнере |
| DSD→PCM | Конвертация DSD в PCM для вывода на обычную звуковую карту |
| WYSIWYG | What You See Is What You Get: визуализация соответствует сигналу на ЦАП |

## 2. Архитектура

### 2.1. Два класса визуализаций

| Класс | Режимы | Источник данных | Когда строится |
|---|---|---|---|
| **Полнотрековый** | Осциллограмма, Спектрограмма | `Decoder` / `DsdDecoder` (отдельный экземпляр, те же настройки) | Один раз при загрузке трека, в фоне, кэшируется |
| **Мгновенный** | Анализатор спектра | cpal callback (tap PCM после всех преобразований) | Непрерывно во время игры |
| — | Отключено | — | — |

### 2.2. Компоненты

```
                            ┌────────────────────────┐
                            │      UI (Slint)        │
                            │  (только отрисовка)    │
                            └────┬──────────────▲────┘
                                 │ команды      │ данные (invoke_from_event_loop)
                                 ▼              │
        ┌──────────────────────────────┐  ┌──────────────────┐
        │  FullTrackWorker             │  │  LiveWorker      │
        │  (отдельный поток)           │  │  (отдельный поток)│
        │  Decoder/DsdDecoder →        │  │  ring → FFT →    │
        │  envelope / spectrogram →    │  │  bars            │
        │  SharedPixelBuffer           │  │                  │
        └────────────┬─────────────────┘  └────────▲─────────┘
                     │                              │
                     ▼                              │
              кэш изображений              cpal callback (tap)
              (LRU + диск)                ┌──────────────────┐
                                          │  PlaybackCore    │
                                          │  → ALSA / cpal   │
                                          └──────────────────┘
```

### 2.3. Поток данных

**Полнотрековая:**
1. `TrackChanged { path }` → UI шлёт в `FullTrackWorker` команду `Build { path, mode }`.
2. Worker открывает трек через **отдельный экземпляр** `AudioSource` (полиморфно: `Decoder` или `DsdDecoder`) с теми же настройками конвертации, что и у основного плеера (WYSIWYG).
3. Читает PCM блоками, накапливает:
   - Осциллограмма: min/max по колонкам → `Vec<(f32, f32)>` на канал.
   - Спектрограмма: FFT по окнам → матрица `[freq_bin][frame]` → цветовая карта.
4. Готовое изображение (`SharedPixelBuffer`) отдаётся в UI через `slint::invoke_from_event_loop`.
5. UI рисует его целиком, поверх — курсор позиции из `Player::snapshot()`.
6. Прогресс `BuildProgress { percent }` во время построения.
7. Отмена (`AtomicBool`) при смене трека/настроек.
8. **Seek во время Build:** Курсор двигается независимо. Построение продолжается. При новом seek или смене трека — отмена текущего билда.

**Мгновенная:**
1. `audio_callback_*` в `player.rs` дополнительно пишет interleaved f32 в lock-free ring buffer (`rtrb`), **только если активен анализатор**. tap до громкости. Данные берутся ПОСЛЕ всех преобразований (ресемплер, (кроме громкости), dither), но ДО отправки в `data` устройства.
2. `LiveWorker` (**в отдельном потоке**) читает буфер, выполняет FFT, формирует полосы.
3. Полосы передаются в UI через `slint::invoke_from_event_loop` для обновления модели.
4. Slint-компонент отрисовывает. Таймер UI (`slint::Timer`) может использоваться как триггер перерисовки (30-60 FPS), но тяжелые вычисления (FFT) выполняются только в worker-потоке.

### 2.4. Ключевые требования к архитектуре
- Аудио-callback **никогда** не блокируется: `try_push` в ring buffer; при переполнении — дроп.
- Оба worker не аллоцируют в горячем цикле: переиспользуемые буферы.
- Все настройки читаются воркером **атомарно на границе кадра**: снимок `Arc<VisualizerSettings>` (через `arc_swap::ArcSwap` или `Arc<Mutex<>>` + `clone`) берётся один раз в начале итерации и не меняется до её конца.
- UI-поток не выполняет FFT или декодирование.
- При смене режима соответствующий worker переинициализируется без перезапуска аудио.
- `FullTrackWorker` и `LiveWorker` взаимоисключающие по режиму: при переключении один останавливается, другой запускается.
- **DeviceChanged:**
  - `LiveWorker`: сбрасывает ring buffer, продолжает работу.
  - `FullTrackWorker`: **не прерывается**, если параметры конвертации DSD→PCM (`target_sr`, `target_bit_depth`, `resampler`) не изменились. Если изменились — отменяет текущий билд и перезапускается с новыми параметрами.

## 6. Обработка DSD

### 6.1. Классификация режимов DSD

| Режим | Вывод на ЦАП | Визуализация |
|---|---|---|
| **DSD → PCM** (обычная звуковая карта) | PCM после `DsdDecoder` (битность/частота по настройкам §8) | **Работает** (как для обычного PCM) |
| **DSD native** | 1-битный DSD-поток напрямую | **Отключена**, плейсхолдер |
| **DoP** | DSD-биты в PCM-контейнере | **Отключена**, плейсхолдер |

### 6.2. DSD → PCM: визуализация (WYSIWYG)

`FullTrackWorker` открывает **отдельный экземпляр** `DsdDecoder` с теми же настройками конвертации (`target_sample_rate`, `target_bit_depth`, `resampler`), что и основной плеер. Это гарантирует идентичность визуализации и звука.

- `LiveWorker` читает ring buffer от cpal — источник PCM безразличен.
- Особенности:
  - `sample_rate` = 44100/48000/88200/96000 (после децимации CIC).
  - `high_boost_db` рекомендуется +3…+6 дБ/декада для компенсации спада CIC (`dsd_cic_compensation = true`).
  - CPU-бюджет: 5-мин DSD64 — 1–3 с на построение; DSD512 — до 30 с. Обязателен прогресс-бар.

### 6.3. DSD native / DoP: визуализация отключена

При активном native/DoP-режиме вывода:
- Все три визуализации недоступны.
- Отображается плейсхолдер:
  - Крупно: «Артист».
  - Крупно: «Альбом».
  - Текст: **«Визуализация недоступна в native DSD / DoP режиме»**.
  - Мельче: название формата, например «DSD64».
- Переключение типа визуализации не приводит к запуску обработки.
- `FullTrackWorker` и `LiveWorker` не запускаются.

**Обоснование:** в native/DoP плеер не декодирует DSD в PCM — на ЦАП идёт 1-битный поток (или его PCM-обёртка). Tap для визуализации отсутствует. Параллельное декодирование через отдельный `DsdDecoder` признано нецелесообразным (двойная нагрузка на CPU, синхронизация курсора с реальным DAC-буфером затруднена, требование заказчика).

### 6.4. Оптимизация для DSD: `skip_fulltrack_for_dsd`

- Настройка `visualization.skip_fulltrack_for_dsd` (bool, default: `true`).
- Если `true` и трек DSD (любой режим): полнотрековая визуализация (осциллограмма/спектрограмма) **не строится**.
- UI показывает сообщение: «Полнотрековая визуализация для DSD отключена (см. настройки)» + Артист/Альбом/Формат.
- Мгновенная визуализация (спектр) работает штатно (если режим DSD→PCM).
- Цель: избежать долгого ожидания построения при старте DSD-трека.

## 7. Bit-perfect режим

### 7.1. Определение
`audio.bit_perfect = true` — вывод без ресемплинга, без софтверной громкости, без DSP. На Linux — через ALSA `hw:X,Y` (exclusive).

### 7.2. Влияние на громкость
Софтверная громкость (`*s *= vol` в `audio_callback_*`) **ломает bit-perfect** и в этом режиме отключается:
- Слайдер громкости заблокирован, подпись «Управляется внешним предусилителем / ОС».
- Mute отключён.
- Ресемплер — passthrough 1:1 (rate/channels совпадают), иначе ошибка открытия устройства или fallback с предупреждением.

### 7.3. Влияние на визуализацию (PCM)
Визуализация — это **tap**, а не модификация потока:
```rust
// в audio_callback_* ПЕРЕД записью в data (или после, но без *)
if visualizer_active && visualizer_mode == Spectrum {
    viz.push(&decoded[..produced]);
}
```
Байты, ушедшие в ЦАП, не меняются. **Bit-perfect сохраняется.**

Полнотрековые визуализации вообще не касаются вывода — они работают через отдельный `Decoder`/`DsdDecoder`, открытый параллельно.

### 7.4. DSD в bit-perfect

| Сценарий | Вывод на ЦАП | Визуализация |
|---|---|---|
| DSD → PCM → DAC | PCM после `DsdDecoder` | Работает (tap), но bit-perfect для DSD **не сохраняется** (DSD→PCM — конверсия) |
| DSD native → DAC | 1-битный поток напрямую | **Отключена** (плейсхолдер) |
| DoP → DAC | DSD-биты в PCM-контейнере | **Отключена** (плейсхолдер) |

### 7.5. Индикация
- В статус-баре — значок «Bit-perfect» (когда активен).
- В настройках звука — чекбокс `bit_perfect`.
- При попытке изменить громкость в bit-perfect — сообщение «Громкость управляется внешним предусилителем / ОС».
- При `bit_perfect = true` и `dsd_to_pcm.enabled = true` — информативное предупреждение: «DSD→PCM несовместимо с bit-perfect для DSD». Пользователь может продолжить, но в статус-баре горит индикатор «Не bit-perfect (DSD→PCM)».

## 8. Настройки DSD → PCM и Ресемплинг

### 8.1. Разделение ответственности

1.  **CIC-децимация внутри `DsdDecoder`**: Превращает 1-битный DSD в PCM с фиксированной частотой (зависит от кратности DSD). Не настраивается пользователем.
2.  **Ресемплинг (`audio.resampler`)**: Если частота PCM (от DSD или FLAC) не совпадает с частотой устройства, применяется универсальный ресемплер.

### 8.2. Расположение настроек

Отдельная вкладка **«DSD»** и раздел **«Звук»** в диалоге настроек.

| Ключ | Секция | Тип | По умолчанию | Описание |
|---|---|---|---|---|
| `dsd.mode` | `[dsd]` | enum | `pcm` | `pcm` / `native` / `dop` |
| `dsd.target_bit_depth` | `[dsd]` | enum | `24` | 16 / 24 / 32 (integer) / 32 (float) |
| `dsd.target_sample_rate` | `[dsd]` | enum | `auto` | auto / 44100 / 48000 / ... / 192000 |
| `audio.resampler.algorithm` | `[audio.resampler]` | enum | `sinc_medium` | linear / cubic / sinc_fast / sinc_medium / sinc_slow / soxr_hq (opt) |
| `audio.resampler.dither` | `[audio.resampler]` | enum | `tpdf` | tpdf / triangular / off |
| `audio.bit_perfect` | `[audio]` | bool | `false` | Режим без изменений потока |

**Примечание:** `resampler.algorithm` применяется ко всем трекам (PCM и DSD), где требуется изменение частоты дискретизации.

### 8.3. Алгоритмы ресемплирования

| ID | Название | Качество | CPU | Применение |
|---|---|---|---|---|
| `linear` | Линейная интерполяция | Низкое | Очень низкий | Быстро, для слабых устройств |
| `cubic` | Кубическая (Catmull-Rom) | Среднее | Низкий | Базовое качество |
| `sinc_fast` | Sinc (короткое окно, 32 тапа) | Хорошее | Средний | Дефолт для realtime |
| `sinc_medium` | Sinc (среднее окно, 64 тапа) | Высокое | Высокий | **Дефолт** |
| `sinc_slow` | Sinc (длинное окно, 128 тапов) | Очень высокое | Очень высокий | Для аудиофилов |
| `soxr_hq` | libsoxr (HQ) | Очень высокое | Высокий | Этап 2, опционально |
| `soxr_vhq` | libsoxr (VHQ) | Максимальное | Очень высокий | Этап 2, опционально |

### 8.4. Взаимодействие с bit-perfect

- При `bit_perfect = true` и `dsd.mode = pcm`:
  - DSD→PCM конвертация **нарушает** bit-perfect (DSD и PCM — разные форматы).
  - UI показывает предупреждение: «DSD→PCM несовместимо с bit-perfect для DSD».
  - Пользователь выбирает: либо native/DoP (bit-perfect, но визуализация отключена), либо DSD→PCM (визуализация работает, bit-perfect для DSD не сохраняется).

### 8.5. Валидация

- `target_sample_rate = auto`: выбирается ближайший поддерживаемый ЦАП (через `cpal` capabilities).
- `target_bit_depth`: если ЦАП не поддерживает выбранную — откат к ближайшей.
- `bit_perfect = true`: ресемплер bypass, если rates не совпадают — ошибка или warning.

### 8.6. UI


### 9.1. Расположение

### 9.2. Структура

```
│                                          │

│                                          │
```

- Выпадающий список: «Отключено», «Осциллограмма», «Спектрограмма», «Анализатор спектра».
- Блок настроек меняется динамически (Slint `if` / `states`).
- «Сбросить настройки типа» — дефолты для текущего типа.

- **Debounce:** При изменении параметров во время построения полнотрековой визуализации — отмена текущего билда, задержка 500 мс, рестарт с новыми параметрами.

- `freq_min < freq_max`.
- `fft_size` — степень двойки из списка.
- `bands` — целое в диапазоне.
- Некорректные значения не применяются, поле подсвечивается.

### 10.2. Загрузка
- При старте приложения.
- Отсутствующие ключи — дефолты.
- Повреждённый файл — дефолты + запись в лог.

### 10.3. Сохранение
- По кнопке «OK» в настройках.
- При выходе из приложения.
- Debounce 500 мс при изменении.

### 10.4. Кэширование изображений
- **Ключ кэша:** `hash(path + mtime + size + mode + channels + params_snapshot + dsd_params)`.
  - `params_snapshot`: все параметры текущего типа визуализации (fft_size, palette, freq_scale, gain_db и т.д.).
  - `dsd_params`: `target_sr`, `target_bit_depth`, `resampler_algorithm` (если трек DSD).
- **Инвалидация:** При смене любого параметра в ключе — старая запись считается невалидной, строится новая.
- **TTL:** Если `mtime` исходного файла новее времени создания кэша — кэш инвалидируется.
- **Лимиты:**
  - Общий лимит RAM для кэша изображений: **64 МБ**. При превышении — LRU-вытеснение старых треков.
  - Лимит на диске: регулируется настройкой `cache.max_size_mb` (default 512 МБ). При превышении — удаление старых файлов.
- **Формат хранения:** PNG (RGBA) + sidecar JSON с метаданными (параметры, размеры).

### 10.5. Управление кэшем (UI)
Вкладка «Дополнительно» или «Кэш»:
- Отображение текущего размера кэша (RAM / Disk).
- Кнопки: «Очистить кэш визуализации», «Очистить кэш обложек», «Очистить всё».

## 11. Производительность

### 11.1. Бюджеты

**Полнотрековые (FullTrackWorker):**
| Параметр | Значение |
|---|---|
| Построение осциллограммы (5 мин) | ≤ 1 с |
| Построение спектрограммы (5 мин, nfft=2048) | ≤ 2 с |
| Построение DSD64→PCM (5 мин) | ≤ 3 с |
| Построение DSD512→PCM (5 мин) | ≤ 30 с (SSD), ≤ 90 с (HDD) |
| Peak RAM при построении | ≤ 128 МБ (nfft=8192, max_frames=4000) |
| CPU | ≤ 1 ядро (100% на время билда) |

**Мгновенные (LiveWorker):**
| Параметр | Значение |
|---|---|
| Задержка отрисовки | ≤ 50 мс |
| Частота обновления UI | 30–60 FPS |
| Нагрузка worker (FFT) | ≤ 5% одного ядра |
| Общая нагрузка на воспроизведение DSD512 | ≤ 20% одного ядра (декодер+ресемплер+callback) |
| Память worker | ≤ 8 МБ |
| Аллокации в горячем цикле | 0 |

**Кэш:**
| Параметр | Значение |
|---|---|
| Общий лимит RAM | ≤ 64 МБ |
| Per-track лимит | Производная от общего (LRU) |

### 11.2. Оптимизации
- FFT — `rustfft` с предвычисленным планом.
- Оконные функции — предвычисленные векторы.
- Ring buffer — `rtrb`.
- Спектрограмма — кольцевой буфер `Vec<u8>`, без переаллокаций.
- Спектр — векторизованное усреднение по бинам (numpy-подобно через `chunks_exact` / итераторы).
- Осциллограмма — min/max по блокам `chunks_exact`.
- Полнотрековые — прогресс + отмена через `AtomicBool`.
- Кэш изображений — LRU на N треков (default 5) + диск.

### 11.3. Адаптация
- При пропуске кадров worker дропает старые сэмплы.
- При resize — перестройка буферов с debounce 100 мс.
- При смене трека — отмена текущего построения.
- При смене настроек — debounced restart (500 мс).

## 12. Отказоустойчивость

| Ситуация | Поведение |
|---|---|
| Ring buffer переполнен | Дроп старых сэмплов |
| FFT не инициализирован | Плейсхолдер + лог |
| Некорректные настройки | Откат к предыдущим валидным |
| DSD native / DoP | Плейсхолдер «Визуализация недоступна» |
| DSD→PCM | Визуализация работает как для PCM |
| Нет аудио (пауза/стоп) | Spectrum затухает, курсор замирает |
| Смена устройства вывода | LiveWorker сбрасывает буфер; FullTrackWorker продолжает, если параметры конвертации не изменились |
| Bit-perfect + попытка изменить громкость | Сообщение «Громкость управляется внешним предусилителем / ОС» |
| Bit-perfect + DSD→PCM | Информативное предупреждение, индикатор «Не bit-perfect» |
| Ошибка открытия трека `FullTrackWorker` | Плейсхолдер + лог |
| Переполнение памяти (DSD512) | Плавная децимация на лету, ошибка «Недостаточно памяти» с fallback на lower quality |
| Seek во время Build | Курсор двигается, Build продолжается. Новый seek отменяет Build. |

## 13. Взаимодействие с плеером

### 13.1. Сигналы от плеера
- `TrackChanged { path, info }` — запуск `FullTrackWorker` (для oscilloscope/spectrogram) или сброс `LiveWorker` (для spectrum); проверка DSD-режима.
- `StateChanged { playing, paused, stopped }` — пуск/пауза обработки.
- `PositionChanged { ms, duration }` — позиционная линия поверх полнотрекового изображения.
- `Seek { ms }` — сброс буфера истории у spectrum (не нужен для полнотрековых — курсор просто перемещается).
- `BitPerfectChanged { enabled }` — блокировка громкости, смена индикации.
- `DsdModeChanged { mode }` — `pcm | native | dop`, влияет на доступность визуализации.
- `DeviceChanged { name }` — сброс буфера LiveWorker; условный рестарт FullTrackWorker.
- `SettingsChanged { params }` — debounced restart workers.

### 13.2. Передача PCM
- Полнотрековые — `FullTrackWorker` открывает `AudioSource` независимо от `Player`.
- Мгновенная — callback пишет в ring buffer **только когда активен анализатор**.
- При `off` запись не ведётся (экономия CPU).
- При bit-perfect PCM — tap работает как обычно.
- При DSD native / DoP — визуализация не запускается.
- При DSD → PCM — визуализация работает как для PCM (tap).

### 13.3. Клик для seek
- Осциллограмма и спектрограмма: клик/драг → `Seek` (координата X → время).
- Анализатор спектра: клик не обрабатывается.

### 13.4. Приоритет плейсхолдеров
1.  **Режим `off`:** Всегда показывать базовый плейсхолдер (Артист/Альбом/Формат). Игнорировать статус DSD.
2.  **Режим активен + DSD Native/DoP:** Показывать спец. плейсхолдер «Визуализация недоступна...» + Артист/Альбом/Формат.
3.  **Режим активен + DSD→PCM + `skip_fulltrack=true`:** Показывать сообщение «Полнотрековая визуализация для DSD отключена» + Артист/Альбом/Формат.

- [ ] Настройки DSD→PCM (битность, частота) и ресемплера работают.
- [ ] Настройки каждого типа визуализации сохраняются и загружаются независимо.

- [ ] Вкладка «DSD» и «Звук» содержат все поля из §8.
- [ ] Стерео и Моно работают для всех трёх типов.
- [ ] Аудио-callback не блокируется (проверка `try_lock`).
- [ ] FPS ≥ 30 при 2048 FFT и 32 полосах (спектр).
- [ ] Нагрузка live-worker ≤ 5% одного ядра.
- [ ] **Нет аллокаций в горячем цикле** (проверка через `heaptrack`/`dhat`).
- [ ] Клик/драг для seek работает на осциллограмме и спектрограмме.

## 16. Этапы разработки

1.  **Каркас**
    - `audio::visualizer`: настройки, `ArcSwap`, сериализация.
    - Slint-компонент `Visualizer` с плейсхолдером.
    - Интеграция с `PlaybackCore`: флаг, tap в ring buffer.

    - `LiveWorker` (отдельный поток): FFT, частотный маппинг, полосы, сглаживание, peak hold.

4.  **Осциллограмма (полнотрековая)**
    - `FullTrackWorker` (отдельный поток): min/max-децимация, прогресс, отмена.
