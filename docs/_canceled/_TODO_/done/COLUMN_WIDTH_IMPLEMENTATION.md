# Инструкция для ИИ-агента: Реализация системы управления шириной колонок плейлиста

## 🎯 Цель
Реализовать robust-систему управления шириной колонок в плейлисте музыкального проигрывателя (Rust + Slint) со следующими характеристиками:
- **Режим "Fit to window"**: колонки всегда заполняют 100% ширины контейнера, горизонтальный скроллбар отсутствует.
- **Ручное изменение**: пользователь перетаскивает разделители между колонками мышью.
- **Кнопка Reset**: сброс всех пропорций к значениям по умолчанию из конфига.
- **Сохранение состояния**: пропорции и порядок сохраняются при выходе, восстанавливаются при запуске.
- **Адаптивность**: корректное поведение при изменении размера окна, скрытии/показе колонок.

## 📂 Часть 1. Структура данных

### 1.1. Статическая конфигурация (`columns_config.toml` / `json`)
Создать файл с дефолтными параметрами для каждой колонки.

**Формат данных:**
```json
{
  "columns": {
    "track": {
      "id": "track",
      "title": "№",
      "priority": 0.03,
      "min_width": 25,
      "max_width": 50,
      "visible_by_default": true,
      "order": 0
    },
    "title": {
      "id": "title",
      "title": "Название",
      "priority": 0.40,
      "min_width": 100,
      "max_width_percent": 0.60,
      "visible_by_default": true,
      "order": 1
    },
    "artist": {
      "id": "artist",
      "title": "Исполнитель",
      "priority": 0.25,
      "min_width": 80,
      "max_width_percent": 0.40,
      "visible_by_default": true,
      "order": 2
    },
    "genre": {
      "id": "genre",
      "title": "Жанр",
      "priority": 0.10,
      "min_width": 60,
      "visible_by_default": false,
      "order": 3
    }
    // ... остальные колонки
  }
}
```

**Критические правила:**
- Для узких колонок (`track`, `duration`, `year`) использовать абсолютный `max_width` (в пикселях).
- Для широких колонок (`title`, `artist`, `album`) использовать относительный `max_width_percent` (доля от ширины контейнера).
- Если ни `max_width`, ни `max_width_percent` не заданы → считать ограничение равным `container_width` (колонка может занять всё доступное место).
- Сумма `priority` не обязана быть 1.0 (нормирование происходит динамически для видимых колонок).

### 1.2. Динамическое состояние пользователя (сохраняется в конфиге)
Хранить в файле настроек пользователя (`config.toml`):

```json
{
  "playlist_layout": {
    "version": 1,
    "visible_columns": ["track", "title", "artist", "album", "duration"],
    "column_order": ["track", "title", "artist", "album", "duration"],
    "column_ratios": {
      "track": 0.04,
      "title": 0.38,
      "artist": 0.26,
      "album": 0.18,
      "duration": 0.14
    }
  }
}
```

**Правила валидации:**
- Ключи в `column_ratios` должны строго соответствовать списку `visible_columns`.
- Сумма значений `column_ratios` должна быть равна 1.0 (с допустимой погрешностью float).
- При первом запуске `column_ratios` инициализируются нормированными `priority` из статического конфига.

## ⚙️ Часть 2. Алгоритмы ядра (Rust)

Реализовать следующие функции в модуле `playlist_layout.rs` (или аналогичном).

### 2.1. Функция нормирования приоритетов
```rust
fn normalize_priorities(
    visible_ids: &[String], 
    static_config: &StaticConfig
) -> HashMap<String, f32> {
    let total_priority: f32 = visible_ids.iter()
        .map(|id| static_config.columns[id].priority)
        .sum();
    
    visible_ids.iter().map(|id| {
        let priority = static_config.columns[id].priority;
        (id.clone(), priority / total_priority)
    }).collect()
}
```

### 2.2. Основной алгоритм распределения (Iterative Distributor)
**Вход:** `container_width`, `visible_columns`, `base_ratios`.
**Выход:** `HashMap<ColumnId, i32>` (финальные ширины в пикселях).

**Логика:**
1. **Инициализация:** Для каждой колонки вычислить `ideal_width = container_width * ratio`. Применить `clamp(ideal, min_width, max_width)`.
   - *Нюанс:* `max_width` вычисляется динамически:
     - Если задан `%`: `max = container_width * percent`.
     - Если задан абсолютный: `max = absolute_value`.
     - **Fallback:** Если ничего не задано → `max = container_width`.
2. **Цикл коррекции (макс. 5-7 итераций):**
   - Посчитать `current_total = sum(widths)`.
   - Вычислить `delta = container_width - current_total`.
   - Если `delta.abs() < 1.0` → выход (достигнута точность пикселя).
   - **Если delta > 0 (Избыток места, нужно добавить ширину):**
     - Найти колонки, которые могут расти: `width < max_width`.
     - Распределить `delta` пропорционально их потенциалу роста (`max_width - width`).
   - **Если delta < 0 (Нехватка места, нужно убрать ширину):**
     - Найти колонки, которые могут сжаться: `width > min_width`.
     - Распределить `abs(delta)` пропорционально их потенциалу сжатия (`width - min_width`).
3. **Финальное округление:**
   - Округлить все ширины вниз до целых.
   - Остаток (`container_width - sum_rounded`) добавить к последней видимой колонке (чтобы сумма была ровно равна ширине контейнера).

### 2.3. Обработчик ручного изменения (Drag & Drop)
Вызывается при перетаскивании разделителя между `LeftCol` и `RightCol`.

**Логика во время движения (mouse move):**
1. Вычислить желаемые новые ширины: `new_left = old_left + delta_x`, `new_right = old_right - delta_x`.
2. Применить жесткие ограничения (`min_width`, `max_width`) к обоим колонкам.
3. Вычислить фактический `actual_delta` (насколько реально сдвинулся разделитель с учетом ограничений).
4. Обновить только эти две колонки в UI модели.
5. **НЕ пересчитывать глобальные ratios на этом этапе.**

**Логика по завершении (mouse release):**
1. Взять текущие финальные ширины всех видимых колонок.
2. Пересчитать `column_ratios`: `ratio[col] = width[col] / container_width`.
3. Сохранить обновленные ratios в состояние (для последующего автосохранения в конфиг).
   - *Причина:* Избегаем накопления ошибок округления float при частых обновлениях во время драга.

### 2.4. Обработчик Reset
1. Взять текущий список `visible_columns`.
2. Получить дефолтные `priority` из статического конфига.
3. Вызвать `normalize_priorities` → получить `default_ratios`.
4. Вызвать **Основной алгоритм распределения** с этими ratios.
5. Применить результат и сохранить в конфиг пользователя.

## 🖥️ Часть 3. Интеграция со Slint UI

### 3.1. Модель данных для Slint
Определить структуру в `.slint` файле:
```slint
struct ColumnLayoutItem {
    id: string,
    title: string,
    width: length,
    visible: bool,
}

component PlaylistView {
    property <[ColumnLayoutItem]> columns_model;
    property <length> container_width;
    
    // ...
}
```

### 3.2. Логика на Rust (Backend)
Создать struct `PlaylistLayoutManager`, который:
- Хранит состояние (`visible_columns`, `ratios`, `order`).
- Слушает события:
  - `on_resize(container_width)`: перезапускает **Основной алгоритм**.
  - `on_drag_move(column_idx, delta_x)`: обновляет ширины двух соседних колонок (без пересчета ratios).
  - `on_drag_release()`: пересчитывает глобальные `ratios` и триггерит сохранение.
  - `on_toggle_visibility(id)`:
    1. Добавить/удалить ID из `visible_columns`.
    2. **Вызвать полный пересчет через Основной алгоритм** (используя текущие или дефолтные ratios для новых колонок). Не пытаться "вычесть" место вручную — алгоритм сам распределит пространство с учетом ограничений.
  - `on_reset()`: запускает **Обработчик Reset**.
- Отправляет обновления в Slint через `ModelRc` или `VecModel`.

**Важно для производительности:**
- При перетаскивании (drag) обновлять модель не чаще 30-60 FPS (использовать таймер или проверку дельты времени), чтобы не перегружать рендерер Slint.
- Передавать в Slint готовый `Vec<ColumnLayoutItem>`, где поле `width` уже вычислено в пикселях.

### 3.3. UI Компоненты
- **Контейнер колонок:** `HorizontalLayout`, где ширина каждого элемента привязана к `model[i].width`.
- **Разделители (Handles):** Тонкие прямоугольники (3-4px) между колонками с обработчиком мыши (`pointer-event`).
  - При `pressed`: запомнить `start_x`.
  - При `moved`: вычислить `delta = current_x - start_x`, вызвать Rust callback `on_drag_move`.
  - При `released`: вызвать Rust callback `on_drag_release`.
  - Курсор: `col-resize` при наведении.

## 💾 Часть 4. Сохранение и Загрузка (Persistence)

### 4.1. Загрузка (Startup)
1. Прочитать конфиг пользователя.
2. **Валидация:**
   - Если файл отсутствует → использовать дефолтные значения из статического конфига.
   - Проверить, что все ID из `visible_columns` существуют в статике. Удалить несуществующие.
   - Если в статике появились новые колонки с `visible_by_default: true`, добавить их в конец списка.
3. Нормировать загруженные `column_ratios` (защита от ошибок округления в старых файлах).
4. Вызвать **Основной алгоритм** с текущей шириной окна.
5. Инициализировать Slint модель.

### 4.2. Сохранение (Shutdown / Debounce)
1. Событие закрытия приложения ИЛИ событие `on_drag_release` / `on_toggle_visibility` (с debounce 1 сек).
2. Сериализовать в JSON/TOML:
   - `visible_columns` (порядок важен).
   - `column_ratios` (текущие пропорции).
3. Записать в файл конфигурации пользователя.

## 🧪 Часть 5. Краевые случаи и тестирование

Проверить следующие сценарии вручную и покрыть юнит-тестами алгоритмы Rust:

1. **Минимальная ширина окна:**
   - Если `container_width` < суммы всех `min_width`:
     - Поведение: пропорционально сжать все колонки, игнорируя `min_width` (предупредить в логе), чтобы интерфейс не сломался.

2. **Максимальная ширина окна:**
   - Если все колонки уперлись в `max_width`, а место осталось:
     - Оставить пустое пространство справа (выравнивание по левому краю) ИЛИ распределить остаток пропорционально между колонками без жесткого лимита (fallback).

3. **Скрытие последней колонки:**
   - Убедиться, что список не становится пустым. Если осталась 0 колонок → показать заглушку "Нет активных колонок".

4. **Добавление новой колонки:**
   - Убедиться, что вызов **Основного алгоритма** корректно перераспределяет место, не нарушая `min_width` других колонок.

5. **Точность округления:**
   - Убедиться, что сумма ширин всегда ровно равна `container_width` (благодаря добавлению остатка к последней колонке).

## ⚠️ Важные замечания для агента
- **Не используй** горизонтальный скроллбар для плейлиста. Основная фича — адаптивная верстка.
- **Избегай** частых аллокаций внутри цикла перетаскивания. Используй предварительное выделение памяти там, где это возможно.
- **Slint специфика:** Изменение свойства `width` у множества элементов может быть дорогим. Старайся обновлять модель одним батчем (`model.set_vec(new_data)`), а не поэлементно в цикле.
- **Логика Delta:** Строго следи за знаками: `delta > 0` → раздать лишнее, `delta < 0` → отнять недостающее.
