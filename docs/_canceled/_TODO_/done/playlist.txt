Я проанализировал код репозитория музыкального плеера, написанный на Rust с использованием фреймворка Slint для UI. Вот мои выводы по интересующим вас аспектам:
1. Интерфейс плейлиста (/workspace/ui/playlist.slint)
Структура:

    Компонент Playlist использует StandardTableView из std-widgets.slint
    Колонки определяются через свойство cols типа [TableColumn]
    Строки через свойство rows типа [[StandardListViewItem]]
    Ширина области просмотра экспортируется как view-width <=> view.visible-width

Проблемы:

    ❌ Отсутствует callback для отслеживания изменения ширины колонок. Когда пользователь изменяет размер колонок мышью (перетаскивая границы в StandardTableView), нет механизма уведомления приложения об этом событии.
    ❌ Нет обработки события columns-changed от StandardTableView, которое должно срабатывать при изменении пользователем ширины колонок.

2. Поведение при изменении размера колонок мышью
Текущая реализация (/workspace/src/app/mod.rs, строки 881-898):
let w = self.ui.get_playlist_view_width() as f32;
if (w - self.last_view_width).abs() > 1.0 && w > 100.0 {
    self.update_column_widths();
    self.last_view_width = w;
}

Проблемы:

    ⚠️ Приложение отслеживает только общую ширину плейлиста через playlist_view_width, но не отдельные колонки
    ⚠️ Механизм сохранения работает через подпись модели колонок (col_model_sig), которая вычисляется из текущих ширин
    ⚠️ Сохранение происходит с задержкой (20 тиков ≈ 2 секунды) после того, как подпись стабилизируется
    ❌ Нет прямого callback'а от StandardTableView о том, что пользователь изменил ширину конкретной колонки

Теперь я понимаю проблему. Давайте проанализируем:
Проблемы:
1. Изменение размера окна мышью не работает
В app.slint окно объявлено как:
export component AppWindow inherits Window {
    title: "Music Player";
    preferred-width: 1200px;
    preferred-height: 760px;
    
    
Свойства preferred-width и preferred-height в Slint задают начальный размер, но окно должно быть изменяемым по умолчанию. Проблема может быть в том, что:

    Нет обработчика события изменения размера окна
    Layout может конфликтовать с изменением размера

2. Изменение ширины колонок
Текущая реализация:

    Отслеживает изменение playlist_view_width на каждом тике (100мс)
    Вычисляет signature колонок (col_model_sig) 
    После 20 тиков (~2 секунды) стабильного состояния сохраняет настройки

Проблема: Код вызывает update_column_widths() при изменении ширины view (строка 883), что перерисовывает колонки на основе сохранённых процентов, а не сохраняет фактические ширины, которые пользователь задал мышью.
3. Нет callback'а от StandardTableView о изменении колонок
В playlist.slint нет обработки события изменения ширины колонок пользователем.
