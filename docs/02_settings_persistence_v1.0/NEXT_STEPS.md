## 1. Замер колёсика на KDE — дозамерить

- [ ] Если `wheel_probe` собран по старой версии промта (нет контрольного шага инверсии) — попросить агента обновить мастер по актуальному `prompt_wheel_test.md` (шаг «инверсия прокрутки включена», автопропуск отсутствующих устройств). Иначе — вручную (ниже).
- [ ] **Контроль инверсии (Wayland):** Параметры системы → Мышь → включить «Инвертировать направление прокрутки» → в мастере только шаги 01 (ползунок, 10 щелчков вверх) и 05 (трей, 10 щелчков вверх) → выключить инверсию. Вопрос: стали ли значения отрицательными.
- [ ] **Сессия X11:** выйти, на экране входа выбрать «Plasma (X11)», прогнать мастер (мышь, ползунок и трей, + контроль инверсии).
- [ ] Результаты положить в `tools/wheel_probe/results/`.
- [ ] **Сессия B агента** по `prompt_wheel_test.md`: оформить `wheel_test.md` (разделы 3–6 по KDE).

Предварительные выводы по KDE Wayland (мышь), чтобы не потерять:
- 1 щелчок = 1 событие, без склейки даже при быстрой прокрутке (интервал до 8–16 мс).
- Ползунок: winit `LineDelta` ±1 → Slint `scroll-event` ±60 px (константа ×60 бэкенда winit Slint 1.17.1). Трей (Plasma → `ksni::scroll`): ±120, `Vertical`.
- «Вверх» положительно у **обоих** источников → в текущем коде трей инвертирован (`delta < 0` → громче) — это баг кода.
- Shift ось не меняет.
- Идея нормализации (гипотеза): у каждого источника своя единица щелчка (ползунок 60 px / 1 строка, трей 120), накопление с переносом остатка, 1 щелчок = 2 %.
