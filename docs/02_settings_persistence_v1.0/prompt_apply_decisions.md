## Решения пользователя (внести дословно по смыслу)

**Решение 1. Два файла и защита от сбоя.**
- `settings.toml` — параметры окна настроек. Пишется только по «Сохранить» (если есть отличия) и при выходе.
- `state.toml` — состояние сессии: активный режим; громкость и mute по режимам (включая mute Строгого режима, решение 3); ширина колонок; сортировка (колонка и направление); тип визуализации; Repeat и Shuffle; геометрия окна; последний каталог. Пишется при выходе и отложенно — через N секунд после последнего изменения (серия изменений даёт одну запись).
- N — параметр окна настроек (хранится в `settings.toml`): 10 / 30 / 60 / 120 с, по умолчанию 30 с.
- Обработчик `SIGTERM`/`SIGINT` ведёт в обычный путь выхода. Аварийной записи из panic-hook нет.
- Все файлы (`settings.toml`, `state.toml`, `playlist.m3u`) пишутся атомарно: временный файл → `fsync` → `rename` → `fsync` каталога (аналоги на Windows/macOS — в спецификации).
- Параметры режимов (SRC, дизеринг, буферы, устройство, DSD→PCM и т. п.) остаются в `settings.toml` и меняются только через диалог; активный режим — в `state.toml` (переключается в главном окне без «Сохранить», как в HQPlayer).
- Основание: практика Audirvana, HQPlayer, Roon (конфигурация через диалог OK/Cancel отдельно от состояния), см. §6 ревью.

**Решение 2. Применение изменений из диалога.**
- Параметры звука (SRC, дизеринг, DSD→PCM, правило частоты, буфер плеера, буфер устройства, флажок фиксации громкости из решения 3) применяются сразу: текущий трек переоткрывается с текущей позиции, состояние воспроизведения (играет / пауза / стоп) сохраняется, все изменения — одним переоткрытием, устройство не освобождается (в Exclusive при необходимости `configure`).
- Смена устройства: освобождение старого → захват нового → продолжение с той же позиции.
- Параметры, не влияющие на звук (цветовая тема, цвета и тип визуализации, её включение/выключение, набор колонок, размер обложки, кэш, сворачивание в трей, интервал N и т. п.), применяются сразу в UI без воздействия на воспроизведение.
- Неизменённые параметры не применяются (никакого перечитывания темы, перестроения модели плейлиста, перечисления устройств без причины).
- Скрытие колонки, по которой отсортирован плейлист, не меняет порядок; ключ сортировки сохраняется, стрелка не видна; при повторном показе колонки стрелка возвращается.

**Решение 3. Громкость и mute.**
- Источники громкости: ползунок, колёсико над ползунком, колёсико над иконкой трея, будущие горячие клавиши. Поведение одинаковое: шаг 2 % за щелчок, одно направление («вверх» — громче), меняется громкость активного режима. Дельты каждого источника нормализуются (мышь и тачпад; KDE, GNOME с расширением AppIndicator, Windows, macOS): накопление до порога одного щелчка, тачпад не даёт десятков шагов за одно движение, системная инверсия прокрутки уважается. Пороги и знаки определяются отдельным экспериментом `wheel_test.md` (промт `prompt_wheel_test.md` готовится отдельно).
- Строгий режим: громкости нет, все источники громкости ничего не делают. **Mute есть** и работает подменой тишиной: трек идёт, позиция движется, на выход — либо исходные биты, либо тишина (для DoP — DoP-тишина с непрерывной фазой маркеров); ни один сэмпл не пересчитывается.
- Оптимальный режим: флажок в настройках режима «Фиксировать громкость на 100 %», по умолчанию выключен, хранится в `settings.toml`. Когда включён — ступени громкости в пути сигнала нет (`NoGain`, как в Строгом режиме, а не умножение на 1); остальные преобразования Оптимального режима (SRC, DSD→PCM с компенсацией, zero-padding, float→int с дизерингом) остаются; mute работает подменой тишиной, как в Строгом. Переключение флажка — параметр звука (решение 2).
- В Совместимом режиме флажка нет.
- Никаких новых элементов интерфейса. Неактивный ползунок громкости / неактивная кнопка показывают причину во всплывающей подсказке при наведении. Кнопка «перейти к настройке» — только внутри этой подсказки и только если это технически возможно в Slint; иначе подсказка — только текст.
- Пока mute включён, бейдж показывает «Mute», а не «Bit-perfect»; после снятия mute вердикт возвращается без переоткрытия трека.
- На границе mute ведёт себя как пауза (мгновенный переход, без плавного затухания).
- Mute хранится в `state.toml` по режимам.

**Решение 4. Куда вносятся решения о звуковом тракте.**
Решения, меняющие модель звукового тракта 01_audio_modes, вносятся прямо в `docs/01_audio_modes_v1.0/` как ОВС-14, ОВС-15, … (с копией в `docs/01_audio_modes_v1.0/02_tz.md`) **отдельной сессией до ТЗ задачи 02**. Задача 02 описывает хранение и UI и ссылается на эти ОВС. В 01 уходят: mute в Строгом режиме подменой тишиной; флажок фиксации громкости (`NoGain`); перенос громкости, mute и активного режима из `ModeSettings` в состояние; `SetModeSettings` — применение без I/O с передачей разницы; применение параметров звука с позиции; поправки ADR-15, ADR-19, §4.2, §6.2, §6.18, §6.27, §6.28 (01_audio_modes). В этой сессии документы 01 не изменяются.

**Решение 5. Запись плейлиста.**
- Флаг «плейлист изменён» в памяти взводится при добавлении, удалении, очистке, загрузке другого плейлиста и ручном изменении порядка. Сортировка флаг не взводит.
- Если флаг взведён, `playlist.m3u` записывается по тому же таймеру N, что и `state.toml`, и при выходе; после записи флаг снимается. Запись атомарная.
- Пункт меню «Сохранить плейлист» — экспорт в файл, выбранный пользователем; на рабочий `playlist.m3u` не влияет.

**Решение 6. Кнопка «Сохранить».**
Неактивна, если в копии нет отличий от действующих настроек или есть недопустимое значение (для недопустимого — причина во всплывающей подсказке при наведении). Закрыть диалог без изменений — «Отмена» или Esc.

**Решение 7. Выход при открытом диалоге.**
Любой путь выхода (закрытие окна, «Выход» в трее, `SIGTERM`/`SIGINT`) при открытом диалоге работает как «Отмена»: копия уничтожается без вопроса, правки диалога в `settings.toml` не попадают; `state.toml` и плейлист записываются как обычно.

**Решение 8. Меню во время диалога.**
Пока открыт диалог настроек, меню главного окна полностью неактивно. Если на какой-то платформе пункты нельзя сделать неактивными — их обработчики ничего не делают, пока диалог открыт. Трей продолжает работать по решениям 3 и 7.

**Решение 9. Повреждённые файлы при запуске.**
- `settings.toml` и `state.toml` разбираются по ключам: отсутствующее или недопустимое значение → значение по умолчанию, остальные сохраняются, замечание в журнал; файл сразу не переписывается (исправления попадут в него при следующей обычной записи).
- Файл не разбирается целиком → значения по умолчанию в памяти; повреждённый файл до первой записи копируется в `settings.toml.bad` / `state.toml.bad` (одна копия, следующая заменяет предыдущую).
- Для `settings.toml` — однократное уведомление в существующей области уведомлений («Файл настроек повреждён, используются значения по умолчанию. Копия: …») и запись в журнал. Для `state.toml` — только журнал.

**Решение 10. Теги и сортировка при запуске.**
Максимально просто: в фоновом потоке читается `playlist.m3u`, затем теги всех файлов, затем применяется сохранённая сортировка; пока идёт загрузка, виден индикатор загрузки; готовый плейлист показывается только после этого. Кэша тегов нет. Библиотека с базой — отдельная будущая задача.
