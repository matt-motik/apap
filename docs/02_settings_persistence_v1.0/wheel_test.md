# Эксперимент: сырые дельты колёсика и тачпада над ползунком Slint и над иконкой трея

Промт: `docs/02_settings_persistence_v1.0/prompt_wheel_test.md`. Статус: **сессия A** — комплект собран, замеров нет.

## 1. Цель и комплект

**Цель.** Получить факты для нормализации колёсика по решению 3 задачи 02 (`01_review.md`), ТЗ-141 и ОВС-20 (01_audio_modes):
- все источники громкости ведут себя одинаково;
- шаг 2 % за щелчок, «вверх» — громче;
- тачпад не даёт десятков шагов за одно движение;
- системная инверсия прокрутки уважается.

**Комплект** — `tools/wheel_probe/` (самостоятельный крейт):
- `README.md` — что это, запуск вручную, формат результатов;
- `OPENCODE.md` — готовый промт для агента opencode на другой ОС;
- `src/main.rs` — мастер замера. Окно Slint с копией ползунка плеера (`ui/top_panel.slint:464-492`) и иконка трея ksni на Linux. В CSV пишутся три источника:
  - `slint` — `scroll-event`;
  - `winit` — сырой `WindowEvent::MouseWheel`: `LineDelta`/`PixelDelta` и `TouchPhase`;
  - `tray` — `ksni::Tray::scroll`: `delta`, `orientation`.
- `results/<os>_<backend>_<desktop>/` — `env.txt`, `summary.txt`, `NN_<device>_<target>_<action>.csv`.

**Шаги мастера:**
- мышь — 4 действия;
- тачпад — 6 действий, при включённой и при выключенной естественной прокрутке;
- высокоточное колесо — 4 действия;
- каждый шаг выполняется над ползунком и над треем. На Linux всего 40 шагов, на Windows и macOS — 20 (без трея).

**Проверка комплекта (Linux, KDE Plasma 6.7.4, Wayland, 2026-09-27):**
- `cargo build --release`, `cargo clippy --release --all-targets -- -D warnings` — без предупреждений; `cargo test` — 2 теста зелёные;
- пробный запуск: бэкенд окна `wayland`, StatusNotifierItem зарегистрирован;
- сборка под Windows и macOS на этой машине не проверялась: нет rustup и целевых платформ. Трей там отключён условной компиляцией (`cfg(target_os = "linux")`).

## 2. Среда

**Версии** (корневой `Cargo.lock`; в `tools/wheel_probe/Cargo.lock` те же): `slint` 1.17.1, `i-slint-backend-winit` 1.17.1, `winit` 0.30.13, `ksni` 0.3.6, `zbus` 5.19.0, `tokio` 1.53.1.

**Как Slint пересчитывает колёсико.** `i-slint-backend-winit-1.17.1/event_loop.rs:403`:
- `MouseScrollDelta::LineDelta(lx, ly)` превращается в `(lx · 60, ly · 60)`;
- `PixelDelta` переводится в логические пиксели по коэффициенту масштаба.

Поэтому `event.delta-y` в `scroll-event` — не число щелчков.

**Ползунок громкости плеера.** `ui/top_panel.slint:464` — `TouchArea` вокруг вертикального `Slider`:
- `scroll-event` (`:471`) реагирует только на `delta-y ≠ 0`;
- шаг ±0,04 за событие независимо от величины дельты, `delta-y > 0` → громче (`:473`);
- Shift и горизонтальная ось не обрабатываются.

**Трей плеера:**

| ОС | Реализация | Где |
|---|---|---|
| Linux | `ksni` 0.3.6 (StatusNotifierItem через D-Bus). `scroll(delta, orientation)` → `TrayCmd::Wheel(delta)`, **ориентация игнорируется** (параметр `_orientation`). В `poll_tray`: шаг 0,02 за событие, важен только знак, `delta < 0` → громче | `src/tray.rs:73`, `src/tray.rs:10` (`TrayCmd`), `src/app/mod.rs:1736-1754` |
| Windows | Отдельной реализации нет. `tray::start()` вызывается безусловно (`src/app/mod.rs:381`), условной компиляции в `src/` нет. Если не удаётся `Tray::spawn` (нет сессионной шины D-Bus и StatusNotifierWatcher), трей молча не создаётся (`src/tray.rs:154`) | — |
| macOS | То же, что Windows | — |

Вывод из кода: на Windows и macOS источника громкости «трей» у плеера сейчас нет. Утверждение «на Windows/macOS `Tray::spawn` всегда завершается ошибкой» получено чтением кода и запуском не проверено.

**Замеры:** данные из `env.txt` каждого замера появятся в §3.
