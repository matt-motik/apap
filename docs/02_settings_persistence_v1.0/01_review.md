Объект: ветка `main`, коммит `e9e4eb7`. Источники требований — `docs/02_settings_persistence_v1.0/prompt_review.md` и `docs/01_audio_modes_v1.0/02_tz.md`, `03_spec.md` (в части хранения — не считаются правильными по умолчанию). ## 1. Вердикт по архитектуре

Хранение настроек построено на принципе «в памяти одна `Settings`, запись при выходе» (комментарии `mod.rs:756`, `mod.rs:1751`, `ui_manager.rs:652`), но принцип не выдержан: файл пишется ещё в семи местах, включая каждый запуск и каждые ~2 с при перемещении окна. Писатель один (`SettingsStore::save`, `settings.rs:1142`), и это хорошая основа, но запись неатомарна, все ошибки молча отбрасываются, всё выполняется в UI-потоке. Защиты от сбоя нет вовсе: `panic = "abort"`, нет обработчика `SIGTERM`/`SIGINT`, нет `Drop`. Диалог настроек работает с копией и частично применяет разницу, но «Сохранить» пишет файл всегда, а применение не дифференциальное: при любом изменении аудио-политик текущий трек перезапускается с начала. Плейлист хранит только пути — при каждом запуске все файлы перечитываются. Документы 01_audio_modes закладывают противоположную модель: запись файла движком при каждом изменении и два писателя одного файла.

## 2. Критические проблемы (блокирующие)

**R-1. Неатомарная запись `settings.toml`, ошибки игнорируются.** `settings.rs:1142-1148`: `let _ = fs::write(&self.path, contents)` — запись поверх файла, без временного файла, `rename`, `fsync`; ошибки сериализации, `create_dir_all` и записи отбрасываются. Проблема: сбой/пропадание питания во время записи оставляет пустой или обрезанный файл (LWN: https://lwn.net/Articles/322823/), а следующий запуск по R-2 молча заменит его значениями по умолчанию. Исправить: запись во временный файл в том же каталоге → `sync_all` → `rename` → `sync_all` каталога (Unix); ошибки типизировать и показывать.

**R-2. Повреждённый файл молча заменяется значениями по умолчанию и перезаписывается при запуске.** `settings.rs:1109`: `toml::from_str(contents).unwrap_or_default()`; `settings.rs:1136-1137`: безусловный `s.save()`. Одна синтаксическая ошибка → все настройки пользователя потеряны без сообщения и без копии. Исправить: при ошибке разбора — не писать файл, сохранить копию (`settings.toml.bad`), сообщение в журнал и UI; коррекции только в памяти.

**R-3. Файл пишется при каждом запуске.** `settings.rs:1137` (комментарий «Persist migration results back to disk» — фактически безусловно). Нарушает главный принцип промта и §6.27 (коррекция при загрузке — только память). Исправить: убрать запись из `load`.

**R-4. Нет записи и освобождения при `SIGTERM`/`SIGINT`, панике.** Обработчиков сигналов нет (`Cargo.toml` без `ctrlc`/`signal-hook`, в `src/` нет `signal`); `Cargo.toml:34-38` `panic = "abort"` — деструкторы не выполняются (https://doc.rust-lang.org/reference/panic.html), panic-hook не установлен; после `run_event_loop_until_quit` (`main.rs:76-79`) ничего не сохраняется; `MusicApp` не имеет `Drop` и [вывод] не освобождается из-за цикла `Rc` (колбэки держат `Rc<RefCell<MusicApp>>`, `MusicApp` держит UI, `mod.rs:235`). Потеря: всё изменённое в памяти с последней записи (громкость, сортировка, колонки, Repeat/Shuffle, тема после «Сохранить» — R-8, грязный плейлист). Исправить: обработчик сигналов → тот же путь выхода; решение о защите от сбоя — вопрос 1 промта.

**R-5. Запись файла мимо правила «выход и „Сохранить“».** Кроме выхода и диалога файл пишут:
- смена типа визуализации из меню и клавишей V: `viz_settings_manager.rs:140`, `:156` (`self.settings.save()` сразу);
- геометрия окна: `ui_manager.rs:73-107` → `save_window_geometry` → `:63`. Это не debounce, а throttle: метка времени ставится по первому изменению и не сбрасывается (`:97-100`), при непрерывном перетаскивании запись каждые ~2 с; при первом запуске без `win_*` — запись через ~2 с после старта. Комментарий `:69` («2 s after the last change») не соответствует коду;
- смена устройства внутри «Сохранить»: `playback_manager.rs:377-378` — пишет **старые** настройки с новым устройством до применения копии (лишняя запись и промежуточное состояние на диске).
Каждая запись сериализует всю `Settings`, поэтому попутно сбрасывает на диск громкость, сортировку, колонки. Исправить: удалить эти вызовы; геометрия и тип визуализации — только память.

**R-6. «Сохранить» пишет файл всегда и 1–3 раза.** `mod.rs:1343` — безусловно; `mod.rs:1370` — вторая запись при смене bit-perfect; `playback_manager.rs:378` — третья при смене устройства. Кнопка активна по `theme-save-enabled` (`settings.slint:1915`, `mod.rs:603`) — это признак валидности темы, а не наличия изменений. Нарушает «только если есть отличия» (краевой случай 2). Исправить: одна запись, только если копия ≠ действующей `Settings`; кнопка — по вопросу 6.

**R-7. Применение при «Сохранить» не дифференциальное; воспроизведение прерывается без нужды.**
- Все 9 сеттеров плеера вызываются всегда (`mod.rs:1391-1399`).
- При изменении любой из 9 аудио-политик текущий трек перезапускается через `play_track(idx)` (`mod.rs:1401-1406`), который открывает трек **с начала** и запускает воспроизведение даже из паузы (`playback_manager.rs:232-280`, `self.player.play()`).
- Если текущий трек DSD — перезапуск при **любом** «Сохранить», даже без изменений DSD (`mod.rs:1414-1419`: условие только `current_track_is_dsd()`).
- Всегда: перечитывание файла темы (`mod.rs:1425-1429`), перестроение модели плейлиста (`:1434`), перечисление устройств (`:1435`).
Нарушает «применяет только изменённые параметры, без полной переинициализации» и краевой случай 10. Исправить: вычислять разницу и способ применения по таблице промта (вопрос 2).

**R-8. Тема из диалога не попадает в файл при «Сохранить».** `mod.rs:1421-1424`: `a.settings.settings.theme = sel` выполняется **после** записи `mod.rs:1343`. Тема записывается только следующей случайной записью (R-5) или при выходе; при панике/`SIGKILL` теряется. Исправить: собрать итоговую `Settings` целиком до единственной записи.

**R-9. Mute не хранится.** `mod.rs:764-767`: `toggle_mute` меняет только плеер, `settings.muted` не обновляется; при запуске восстанавливается старое значение (`mod.rs:361`). `settings.muted` меняется только в ветках bit-perfect (`mod.rs:1365`, `bp_report.rs:190`). Исправить: mute — часть настроек режима (ТЗ-93 (01_audio_modes): `muted` в `CompatibleOpts`/`OptimalOpts`).

**R-10. Отсутствующий ключ даёт недопустимое значение без проверки.** `#[serde(default)]` для `volume`, `cover_size`, `col_info_w`, `col_gap` (`settings.rs:734-735`, `:765-775`) даёт `0`/`0.0`, а не значения `impl Default` (`:820-853`: 0.8, 200, 240, 12). Файл без `volume` → тишина; `cover_size = 0` уходит в UI без ограничения (`ui_manager.rs:137-141`). Исправить: `#[serde(default = "...")]` или DTO + валидация при загрузке с заметкой (как `load_mode_settings`, §6.27 (01_audio_modes)).

**R-11. Диалог настроек модален только визуально.** Диалог — `Rectangle` поверх окна (`ui/settings.slint:47`, `app.slint:602-605`), фон перехватывает указатель (`settings.slint:220-228`), `FocusScope` и клавиша V отключены (`app.slint:383-386`). Не блокируются:
- пункты нативного `MenuBar` «Файл» (добавить файлы/папку, сохранить/загрузить плейлист) и «Настройки → Параметры» (`app.slint:37-56`, `:92-95`); повторный выбор «Параметры» пересоздаёт копию (`mod.rs:821`) — **несохранённые правки диалога теряются**;
- трей: «Выход» во время диалога выбрасывает копию без вопроса (`mod.rs:1592`, `:1725-1735`); громкость, Play/Next/Prev работают (`tray.rs:9-18`).
Нативной модальности в Slint/winit нет: PR https://github.com/slint-ui/slint/pull/8135 открыт, winit возвращает `Unsupported`; issue https://github.com/slint-ui/slint/issues/6607. Оверлей внутри окна — единственный переносимый вариант на Linux (X11/Wayland), Windows, macOS (одинаково, т. к. не зависит от оконной системы) — но блокировать нужно всё, включая `MenuBar`.

**R-12. Значения, изменённые мимо диалога, частично откатываются «Сохранить».** `mod.rs:1314-1342` переносит из действующих настроек в копию только `volume, muted, last_dir, repeat, shuffle, sorted_col, sort_desc, win_x/y/w/h`. Не переносятся `win_fullscreen`, `win_maximized` и ширины колонок (`columns[*].width`, обновляются по `tick`, `mod.rs:1614-1627`) — изменённые во время открытого диалога значения затираются устаревшей копией. Модель «копия всего `Settings`, потом белый список живых полей» хрупкая: каждое новое поле состояния надо не забыть. Исправить: диалог редактирует только свои параметры (отдельная структура), состояние сессии в копию не входит.

**R-13. Файловый ввод-вывод в UI-потоке.** Все записи настроек (W1–W7, см. §4.1) и плейлиста; «Загрузить плейлист» синхронно читает файл и зондирует **каждый** трек (`mod.rs:885` → `playlist.rs:95-100` → `meta::probe_file`); чтение тем при открытии диалога и выборе (`mod.rs:609-644`); обход каталогов кэша каждые 100 мс, пока открыт диалог (`mod.rs:1609-1611` → `fulltrack.rs:325-336`, `cover.rs:106-118`); `fs::metadata` текущего трека каждый тик (`fulltrack_manager.rs:413`); блокирующие `rfd::FileDialog` (`mod.rs:844-883`). Нарушает «запись файлов не в UI-потоке».

**R-14. Плейлист без тегов: каждый запуск перечитывает все файлы.** M3U содержит только абсолютные пути (`playlist.rs:226-241`), без `#EXTINF`; кэша тегов нет; `Track` не сериализуется (`playlist.rs:20-48`). При запуске каждый путь проходит `meta::probe_file` (`playlist.rs:221`, `:100`; `meta.rs:129-211`) последовательно в одном потоке (`mod.rs:375-378`). Сохранённая сортировка применяется только после полного зондирования (`mod.rs:1674-1677`). Нарушает «сортировка при запуске без повторного чтения всех аудиофайлов».

**R-15. Ошибки в «Загрузить плейлист» и гонка при запуске.** `mod.rs:885-893`: сохранённая сортировка не применяется (а стрелка в заголовке остаётся, `ui_manager.rs:563-571`); `current = None` без остановки плеера; `playlist_dirty` не ставится — загруженный список не попадёт в `playlist.m3u`. [предположение] Гонка: `drain_startup_tracks` выполняется до `drain_scan` в одном тике (`mod.rs:1594-1595`) и перезаписывает `tracks`, `disk_tracks`, `known_paths` (`:1670-1672`) — добавленные до окончания стартовой загрузки треки пропадут при `playlist_dirty = true`.

**R-16. Тест пишет настоящий `settings.toml` пользователя.** `bp_report.rs:205-207` `bp_report_marks_volume_issue` создаёт `MusicApp::new`, а `SettingsStore::load` безусловно пишет `config_dir()/settings.toml` (R-3), создаёт темы и запускает трей и поток загрузки плейлиста. Каждый `cargo test` перезаписывает конфиг пользователя.

### 3.4. Громкость
- Колёсико над ползунком — шаг 0,04 (`top_panel.slint:473`), трей — 0,02 (`mod.rs:1737`); комментарий `top_panel.slint:468` «same step as the tray» неверен. Направление: в Slint `delta-y > 0` — громче, в трее `delta < 0` — громче. **Требование «так же, как в трее» не выполнено.**
- Трей двигает ползунок: `sync_playback_state_to_ui` раз в 100 мс читает `player.volume()` (`playback_manager.rs:9-35`). [предположение] После перетаскивания ползунка привязка `value: root.volume` (`top_panel.slint:484`) может быть перезаписана Slint, и ползунок перестанет следовать за треем — проверить запуском.
- Громкость одна на всё приложение (`settings.rs:734-737`), не по режимам (ТЗ-93 (01_audio_modes)) — ожидаемо до этапа С4 (01_audio_modes).
- Bit-perfect: ползунок и колёсико отключены (`top_panel.slint:467`, `:488`), Rust-guard `mod.rs:751-753`; трей игнорирует громкость по флагу `bit_perfect`, а не по режиму (`mod.rs:1743`). Выключение bit-perfect не возвращает прежнюю громкость — остаётся 1,0 (`mod.rs:1357-1373`).
- Ни одно изменение громкости не пишет файл напрямую — соответствует; но попадает на диск с любой случайной записью (R-5).

### 3.5. Визуализация
Смена типа из меню и клавишей V пишет файл сразу (R-5) — не соответствует.

### 3.6. Плейлист и сортировка
- Сортировка не пишет плейлист — соответствует. Хранятся колонка и направление (`settings.rs:754-757`) — соответствует.
- Два списка: `disk_tracks` — исходный порядок (пишется в файл, `playlist_manager.rs:94-100`), `tracks` — видимый. Порядок воспроизведения — видимый (`playlist.rs:154-177` по индексам `tracks`) — соответствует. Сортировка стабильная (`sort_by`, `playlist_manager.rs:166`) — соответствует.
- Недостатки: нет возврата к исходному порядку (`sorted_col` только `Some`, `:180`); результаты сканирования добавляются в конец отсортированного списка без пересортировки (`playlist_manager.rs:52`, `:79`) — видимый порядок перестаёт соответствовать ключу; клик по колонке «Сейчас играет» переключает стрелку, но не сортирует (`:161-163`); сравнение текста побайтовое, регистрозависимое; год — строкой; номер диска игнорируется (`playlist.rs:290-323`).
- Перетаскивания строк нет (`ui/playlist.slint:44-54`, `tableview_fork.slint`) — требование «перетаскивание сбрасывает ключ» пока нечем выполнить.
- Сортировка во время воспроизведения: `current` и `shuffle_order` переотображаются (`playlist_manager.rs:175-178`) — трек не меняется. Shuffle пересоздаётся при добавлении/удалении/очистке/загрузке (`playback_manager.rs:301-314`) с потерей истории; [вывод] при Repeat Off треки перед текущей позицией новой перестановки не будут сыграны. Серии пропусков в коде ещё нет (этап С8 (01_audio_modes)).
- «Далее» при `current = None` играет индекс 1, а не 0 (`playlist.rs:154-177`, закреплено тестом `playlist.rs:371`).
- Моменты записи плейлиста: выход (если изменён) и «Сохранить плейлист» в меню; изменения состава помечают `playlist_dirty` (`playlist_manager.rs:10-146`); атомарно (`.tmp` + `rename`, `playlist.rs:236-240`), без `fsync`, в UI-потоке. «Сохранение» для плейлиста сейчас = выход или явная команда меню (вопрос 5).

### 3.7. Надёжность
Атомарна только запись плейлиста (без `fsync`). `settings.toml`, темы, кэши обложек и визуализации — прямая запись (`cover.rs:330-337`, `fulltrack.rs:384-402`). При сбое: паника — теряется всё с последней записи (R-4); `SIGKILL` — то же; пропадание питания во время записи `settings.toml` — пустой/обрезанный файл → молчаливый сброс (R-1+R-2).

## 4. Оценка ключевых механизмов

### 4.1. Загрузка и запись `settings.toml`
Писатель один, мест вызова семь: W1 `settings.rs:1137` (запуск), W2 `ui_manager.rs:63` (геометрия, выход, трей), W3 `playback_manager.rs:378` (устройство), W4 `mod.rs:1343`, W5 `mod.rs:1370` («Сохранить»), W6 `viz_settings_manager.rs:140`, W7 `:156`. Все синхронно в UI-потоке. Путь `dirs::config_dir()/music_player/settings.toml` (`settings.rs:1192-1206`). Разбор — весь документ или ничего (`unwrap_or_default`); миграция старых колонок (`:1114-1129`).

### 4.2. Диалог
Оверлей, копия всей `Settings` (`mod.rs:821`), белый список «живых» полей при «Сохранить» (`mod.rs:1314-1342`), частичная разница (кэш RAM, bit-perfect, кортеж политик), безусловная запись. См. R-6, R-7, R-8, R-11, R-12.

### 4.3. Источники громкости
Ползунок, колёсико над ползунком, колёсико трея, действия отчёта bit-perfect (`bp_report.rs:183-191`), включение bit-perfect (`mod.rs:1357-1373`), запуск (`mod.rs:360-361`). Все ведут в `Player::set_volume` (атомик, `player.rs:879-884`, `worker.rs:114-116`). Колёсика над иконкой трека/обложкой нет. Горячих клавиш, MPRIS, медиаклавиш нет.

### 4.4. Плейлист
Путь `config_dir()/playlist.m3u`; только пути; дубликаты удаляются; несуществующие файлы остаются в списке (фильтр только по расширению, `playlist.rs:219`). Теги — зондирование при запуске и повторно при воспроизведении (`playback_manager.rs:239-275`, пишется в `tracks`, не в `disk_tracks`).

### 4.5. Выход и сбой
`close_requested`/трей: геометрия+настройки → плейлист (если изменён) → `release_engine` → `quit_event_loop` (`mod.rs:1566-1584`, `:1725-1735`). Одна запись настроек на выход — соответствует. Сигналы и паника — R-4.

Сортировка: foobar2000 (`playlist_reorder_items`), DeaDBeeF (`plt_sort` перестраивает список), Audacious, Strawberry/Clementine (команда отмены) — **сортировка меняет порядок элементов плейлиста навсегда**; хранения «ключа сортировки поверх исходного порядка» у них нет. Выводы: (1) все, кроме старого foobar2000, разделяют «конфигурацию» и «состояние сессии» или хотя бы пишут только при изменении; (2) защита от сбоя — отложенная запись (MPD 120 с, Audacious 5 мин, Strawberry 900 мс) или транзакционная БД (foobar2000 v2); (3) атомарность через `rename` — стандарт (MPD, DeaDBeeF, Qt), `fsync` делают немногие; LWN фиксирует потерю данных на ext4 без него (https://lwn.net/Articles/322823/).

Атомарная запись на ОС: Linux/macOS — `rename(2)` атомарен (https://man7.org/linux/man-pages/man2/rename.2.html), для долговечности нужен `fsync` каталога (https://man7.org/linux/man-pages/man2/fsync.2.html); Rust `File::sync_all` на macOS использует `F_FULLFSYNC`, на Windows — `FlushFileBuffers`; `std::fs::rename` на Windows — `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` (https://github.com/rust-lang/rust/blob/master/library/std/src/sys/fs/windows.rs). Крейт `atomicwrites` делает `sync_all` + `rename` + `sync_all` каталога и `MOVEFILE_WRITE_THROUGH` на Windows; `tempfile::persist` не синхронизирует. Panic-hook выполняется и при `panic = "abort"` (https://doc.rust-lang.org/std/panic/fn.set_hook.html) — возможна аварийная запись. Сигналы: `ctrlc` (фича `termination`) или `tokio::signal` (уже выбрано в §6.28 (01_audio_modes)) + `slint::invoke_from_event_loop`.

## 7. Оптимизация

- Убрать запись при запуске и лишние записи (R-3, R-5, R-6): сейчас при перемещении окна — запись каждые 2 с.
- Кэш тегов (например `#EXTINF` или отдельный файл данных) — запуск без зондирования N файлов (R-14).
- Сортировка клонирует каждый `Track` (`playlist_manager.rs:170`) — перестановка индексов вместо клонирования; `disk_tracks` клонирует список при загрузке (`mod.rs:887`, `:1670`).
- `visualization.clone()` каждые ~33 мс (`visualizer_manager.rs:55`), `VisualizerConfig::from_settings` каждый тик (`fulltrack_manager.rs:377-378`).
- Обход каталогов кэша каждые 100 мс при открытом диалоге (`mod.rs:1609-1611`) — считать при открытии и после очистки.
- «Сохранить» перестраивает всю модель плейлиста и перечисляет устройства всегда (`mod.rs:1434-1435`).

## 8. Примеры рефакторинга «Было / Стало»

**Запись настроек.** Было (`settings.rs:1142-1148`):
```rust
pub fn save(&mut self) {
    if let Ok(contents) = toml::to_string(&self.settings) {
        if fs::create_dir_all(self.path.parent().unwrap_or(&self.path)).is_ok() {
            let _ = fs::write(&self.path, contents);
        }
    }
}
```
Стало (гипотеза, не требование):
```rust
#[derive(Debug)]
pub enum SaveError { Serialize(toml::ser::Error), Io(std::io::Error) }

pub fn save_atomic(path: &Path, settings: &Settings) -> Result<(), SaveError> {
    let text = toml::to_string(settings).map_err(SaveError::Serialize)?;
    let dir = path.parent().ok_or_else(|| SaveError::Io(io::ErrorKind::NotFound.into()))?;
    fs::create_dir_all(dir).map_err(SaveError::Io)?;
    let tmp = dir.join("settings.toml.tmp");
    let mut f = File::create(&tmp).map_err(SaveError::Io)?;
    f.write_all(text.as_bytes()).map_err(SaveError::Io)?;
    f.sync_all().map_err(SaveError::Io)?;          // F_FULLFSYNC на macOS, FlushFileBuffers на Windows
    fs::rename(&tmp, path).map_err(SaveError::Io)?; // MoveFileExW(REPLACE_EXISTING) на Windows
    #[cfg(unix)] File::open(dir).and_then(|d| d.sync_all()).map_err(SaveError::Io)?;
    Ok(())
}
```

**Загрузка.** Было: `toml::from_str(contents).unwrap_or_default()` + `s.save()`. Стало: `Result`: при ошибке разбора — `Settings::default()` в памяти, файл не трогать, копия `settings.toml.bad`, заметка; `load` не пишет.

**«Сохранить».** Было: копия всей `Settings` + белый список живых полей + безусловная запись + перезапуск трека с начала. Стало: `DialogDraft` содержит только параметры диалога; `diff(&current, &draft) -> SettingsDiff`; пустая разница → ничего; иначе применение по способу для каждого поля и одна запись.

**Mute.** Было: `app.borrow_mut().player.toggle_mute();`. Стало: `let m = !a.player.muted(); a.player.set_muted(m); a.settings.settings.muted = m;` (память).

## Решения пользователя

Решения обязательны и имеют приоритет над предложениями ревью и над требованиями промта, если противоречат им.

1. **Два файла и защита от сбоя.**
   - `settings.toml` — параметры окна настроек. Пишется только по «Сохранить» (если есть отличия) и при выходе.
   - `state.toml` — состояние сессии: активный режим; громкость и mute по режимам (включая mute Строгого режима, решение 3); ширина колонок; сортировка (колонка и направление); тип визуализации; Repeat и Shuffle; геометрия окна; последний каталог. Пишется при выходе и отложенно — через N секунд после последнего изменения (серия изменений даёт одну запись).
   - N — параметр окна настроек (хранится в `settings.toml`): 10 / 30 / 60 / 120 с, по умолчанию 30 с.
   - Обработчик `SIGTERM`/`SIGINT` ведёт в обычный путь выхода. Аварийной записи из panic-hook нет.
   - Все файлы (`settings.toml`, `state.toml`, `playlist.m3u`) пишутся атомарно: временный файл → `fsync` → `rename` → `fsync` каталога; аналоги на Windows и macOS — в спецификации.
   - Параметры режимов (SRC, дизеринг, буферы, устройство, DSD→PCM и т. п.) остаются в `settings.toml` и меняются только через диалог. Активный режим — в `state.toml`: переключается в главном окне без «Сохранить», как в HQPlayer.
   - Активный режим меняется только в главном окне. В диалоге настроек режим выбирается только для редактирования параметров этого режима; этот выбор не меняет активный режим и не хранится.
   - Основание пользователя: практика HQPlayer, Audirvana, Roon — конфигурация через диалог OK/Cancel отдельно от состояния. HQPlayer Desktop: диалог настроек «OK» сохраняет, «Cancel» отбрасывает; выбор фильтра, oversampling и noise-shaping — в главном окне; громкость — колёсико, мультимедиа-клавиши, пульт; диапазон громкости 0…0 полностью отключает регулятор (руководства https://www.sonore.us/HQPlayer-manual.pdf, https://cdn.head-fi.org/a/12503835.pdf). Audirvana: плейлисты, критерии сортировки и фильтры — в `AudirvanaDatabase.sqlite` (https://community.audirvana.com/t/studio-backup-restore-database-parameters/28647). Roon: состояние — в базе сервера `RoonServer/Database` (https://help.roonlabs.com/portal/en/kb/articles/roon-os-data-directory); Fixed Volume «disables volume control from within Roon» (https://help.roonlabs.com/portal/en/kb/articles/audio-setup-basics). Где хранятся параметры звука Audirvana и HQPlayer и когда пишутся — не подтверждено.
   - Основание: R-1, R-3, R-4, R-5, R-12; §3.1, §3.7, §6 ревью; вопрос 1 промта.

2. **Применение изменений из диалога.**
   - Параметры звука (SRC, дизеринг, DSD→PCM, правило частоты, буфер плеера, буфер устройства, флажок фиксации громкости из решения 3) применяются сразу: текущий трек переоткрывается с текущей позиции, состояние воспроизведения (играет / пауза / стоп) сохраняется, все изменения — одним переоткрытием, устройство не освобождается (в Exclusive при необходимости `configure`).
   - Смена устройства: освобождение старого → захват нового → продолжение с той же позиции.
   - Параметры, не влияющие на звук (цветовая тема, цвета и тип визуализации, её включение и выключение, набор колонок, размер обложки, кэш, сворачивание в трей, интервал N и т. п.), применяются сразу в UI без воздействия на воспроизведение.
   - Неизменённые параметры не применяются: без перечитывания темы, перестроения модели плейлиста и перечисления устройств без причины.
   - Скрытие колонки, по которой отсортирован плейлист, не меняет порядок: ключ сортировки сохраняется, стрелка не видна; при повторном показе колонки стрелка возвращается.
   - Основание: R-7, R-8; §3.3 ревью; вопрос 2 промта.

3. **Громкость и mute.**
   - Источники громкости: ползунок, колёсико над ползунком, колёсико над иконкой трея, будущие горячие клавиши. Поведение одинаковое: шаг 2 % за щелчок, одно направление («вверх» — громче), меняется громкость активного режима.
   - Дельты каждого источника нормализуются (мышь и тачпад; KDE, GNOME с расширением AppIndicator, Windows, macOS): накопление до порога одного щелчка, тачпад не даёт десятков шагов за одно движение, системная инверсия прокрутки уважается. Пороги и знаки определяются отдельным экспериментом `wheel_test.md` (промт `prompt_wheel_test.md` готовится отдельно).
   - Строгий режим: громкости нет, все источники громкости ничего не делают. **Mute есть** и работает подменой тишиной: трек идёт, позиция движется, на выход — либо исходные биты, либо тишина (для DoP — DoP-тишина с непрерывной фазой маркеров); ни один сэмпл не пересчитывается.
   - Оптимальный режим: флажок в настройках режима «Фиксировать громкость на 100 %», по умолчанию выключен, хранится в `settings.toml`. Когда включён — ступени громкости в пути сигнала нет (`NoGain`, как в Строгом режиме, а не умножение на 1); остальные преобразования Оптимального режима (SRC, DSD→PCM с компенсацией, zero-padding, float→int с дизерингом) остаются; mute работает подменой тишиной, как в Строгом. Переключение флажка — параметр звука (решение 2).
   - В Совместимом режиме флажка нет.
   - В Совместимом режиме и в Оптимальном без флажка фиксации все источники громкости работают, включая трей (ответ на вопрос 3 промта).
   - При включённом флажке фиксации ползунок, колёсико над ползунком, колёсико над иконкой трея и горячие клавиши громкость не меняют (ничего не делают); mute работает подменой тишиной.
   - Никаких новых элементов интерфейса. Неактивный ползунок громкости или неактивная кнопка показывают причину во всплывающей подсказке при наведении. Кнопка «перейти к настройке» — только внутри этой подсказки и только если это технически возможно в Slint; иначе подсказка — только текст.
   - Пока mute включён, бейдж показывает «Mute», а не «Bit-perfect»; после снятия mute вердикт возвращается без переоткрытия трека.
   - На границе mute ведёт себя как пауза: мгновенный переход, без плавного затухания.
   - Mute хранится в `state.toml` по режимам.
   - Основание: R-9, R-22; §3.4, §4.3 ревью; вопрос 3 промта.

4. **Куда вносятся решения о звуковом тракте.** Решения, меняющие модель звукового тракта 01_audio_modes, вносятся прямо в `docs/01_audio_modes_v1.0/` как ОВС-14, ОВС-15, … (с копией в `docs/01_audio_modes_v1.0/02_tz.md`) **отдельной сессией до ТЗ задачи 02**. Задача 02 описывает хранение и UI и ссылается на эти ОВС. В 01 уходят: mute в Строгом режиме подменой тишиной; флажок фиксации громкости (`NoGain`); перенос громкости, mute и активного режима из `ModeSettings` в состояние; `SetModeSettings` — применение без I/O с передачей разницы; применение параметров звука с позиции; поправки ADR-15, ADR-19, §4.2, §6.2, §6.18, §6.27, §6.28 (01_audio_modes). В сессии внесения решений в ревью документы 01 не изменяются.
   - Основание: R-17…R-24; §5 ревью; вопрос 4 промта.

5. **Запись плейлиста.**
   - Флаг «плейлист изменён» в памяти взводится при добавлении, удалении, очистке, загрузке другого плейлиста и ручном изменении порядка. Сортировка флаг не взводит.
   - Если флаг взведён, `playlist.m3u` записывается по тому же таймеру N, что и `state.toml`, и при выходе; после записи флаг снимается. Запись атомарная.
   - Пункт меню «Сохранить плейлист» — экспорт в файл, выбранный пользователем; на рабочий `playlist.m3u` не влияет.
   - Основание: R-15; §3.6, §3.8 ревью; вопрос 5 промта.

6. **Кнопка «Сохранить».** Неактивна, если в копии нет отличий от действующих настроек или есть недопустимое значение (для недопустимого — причина во всплывающей подсказке при наведении). Закрыть диалог без изменений — «Отмена» или Esc.
   - Основание: R-6; §3.9 п. 2 ревью; вопрос 6 промта.

7. **Выход при открытом диалоге.** Любой путь выхода (закрытие окна, «Выход» в трее, `SIGTERM`/`SIGINT`) при открытом диалоге работает как «Отмена»: копия уничтожается без вопроса, правки диалога в `settings.toml` не попадают; `state.toml` и плейлист записываются как обычно.
   - Основание: R-11; §3.3 ревью.

8. **Меню во время диалога.** Пока открыт диалог настроек, меню главного окна полностью неактивно. Если на какой-то платформе пункты нельзя сделать неактивными — их обработчики ничего не делают, пока диалог открыт. Трей продолжает работать по решениям 3 и 7.
   - Основание: R-11; §3.3 ревью.

9. **Повреждённые файлы при запуске.**
   - `settings.toml` и `state.toml` разбираются по ключам: отсутствующее или недопустимое значение → значение по умолчанию, остальные сохраняются, замечание в журнал; файл сразу не переписывается (исправления попадут в него при следующей обычной записи).
   - Файл не разбирается целиком → значения по умолчанию в памяти; повреждённый файл до первой записи копируется в `settings.toml.bad` / `state.toml.bad` (одна копия, следующая заменяет предыдущую).
   - Для `settings.toml` — однократное уведомление в существующей области уведомлений («Файл настроек повреждён, используются значения по умолчанию. Копия: …») и запись в журнал. Для `state.toml` — только журнал.
   - Основание: R-2, R-3, R-10; §3.9 п. 6 ревью.

10. **Теги и сортировка при запуске.** Максимально просто: в фоновом потоке читается `playlist.m3u`, затем теги всех файлов, затем применяется сохранённая сортировка; пока идёт загрузка, виден индикатор загрузки; готовый плейлист показывается только после этого. Кэша тегов нет. Библиотека с базой — отдельная будущая задача.
    - Основание: R-14, R-15; §3.6 ревью.

11. **Громкость Совместимого режима по умолчанию — 100 %.** Совпадает с Оптимальным режимом (ОВ-5 (01_audio_modes)): плеер по умолчанию не ослабляет сигнал, громкость регулирует система. Значение по умолчанию `PlaybackState::compatible.volume` (01_audio_modes, §2.2) — 100 %; сейчас в коде 0.8 (`settings.rs:824`, `impl Default for Settings`, `settings.rs:820-853`).
    - Основание: ТС-5 (`docs/01_audio_modes_v1.0/03_spec.md`, §11, «Толкования при внесении ОВС-14…»); R-10.
