## К §9 спецификации: известные риски — оформить как ОВС, если не решаются однозначно по источникам

1. **Инерция на macOS.** ТЗ-36 требует отбрасывать инерционные события на macOS, но winit 0.30.13 не помечает инерцию отдельным признаком (`wheel_test.md` §2, §4.6). Варианты: узкий macOS-путь в модуле ввода с фазой инерции из `NSEvent`; распознавание инерции по последовательности фаз winit (`Ended` пальцев, затем новая серия `Started…Ended` без касания), если исходник это подтверждает; ограничение K на свайп, как на Windows, — **меняет ТЗ-36** (для macOS там «инерционные события игнорируются»), поэтому допустимо только как вариант ОВС с пометкой «меняет требование», не как молчаливый выбор; иное.
2. **Бэкенд Slint не winit или окно winit недоступно.** В замере GNOME-2 окно winit не было получено за 300 мс (`wheel_test.md` §2.2, `not-winit`). Нужно: гарантировать бэкенд winit или описать запасной путь (правило по умолчанию на значениях Slint) и момент подключения хука.
3. **Feature `unstable-winit-030` в основном крейте плеера** — проверь `Cargo.toml`; если её нет — решение о добавлении, последствия для обновления Slint.
