# AGENTS.md

> НАЧАЛО СЕССИИ: первым действием `git pull`, затем прочитай `_STATE_.yaml` (не `_STATE_.md` — это сгенерированное представление для человека) и до любой правки выполни `docs/00_workflow_v1.0/planning.md` §1–2: режим сессии («Продолжение» при `status: in_progress`, иначе «Новая задача»), проверка репозитория, выбор задачи.

## Продукт и приоритеты

APAP — аудиофильский плеер (Rust + Slint). Когда спека не даёт ответа (выбор решения, приоритет бага), порядок такой:

1. **Честность сигнала** — плеер никогда не заявляет bit-perfect, если это не так, и не меняет сигнал молча.
2. **Безопасность слуха и оборудования** — скачок громкости, DoP на ЦАП без DoP, полная шкала → баг 🔴.
3. **Надёжность реального времени** — без дропаутов и заиканий.
4. **Удобство** интерфейса.

При сомнении выбирай вариант, сохраняющий сигнал, и спрашивай пользователя. Платформы: Linux (ALSA, PipeWire), Windows (WASAPI, ASIO), macOS (CoreAudio). Ветки `cfg` другой ОС локально не компилируются — их проверяет ревью, а сборка на другой машине записывается в `note` пункта плана.

## Артефакты и доступ

Нарушение правил доступа — критическая ошибка.

- `_STATE_.yaml` — состояние текущей сессии и единственный файл состояния (схема — `tools/schema/state.schema.json`): читаешь и правишь только его; `plan-*.md`, `.current-plan.json` и подобные создавать запрещено. `_STATE_.md` генерируется командой `python tools/state_tool.py render`, руками не правится (блокирует pre-commit), агент его не читает. Многошаговый план поверх сессий — поле `plan:`.
- Пользователь работает на двух машинах; между ними переносится **только git** (`_STATE_.yaml`, `ROADMAP.md`, `docs/`). Память агента, задачи и подтверждения в чате не переносятся: что не закоммичено, для следующей сессии не существует.
- `ROADMAP.md` — единый технический бэклог: задачи = этапы спецификаций и баги. Правится точечно (одна строка, соседние не затираются) и согласованно с `_STATE_.yaml`. Порядок этапов **внутри** спецификации не меняется; порядок **между** спецификациями задаёт только раздел «Сквозной порядок этапов» в `ROADMAP.md`.
- `docs/` — действующая документация, папки `docs/NN_имя_vX.Y/`; правится ТОЛЬКО по явному разрешению пользователя (просьба изменить закреплённый в спеке текст — разрешение на это место, `task_intake.md` §5; результаты приёмки пишет `tools/acceptance.py` без отдельного разрешения). Действующие спеки продукта: `docs/01_audio_modes_v1.0/` (`AM1.0`, аудио-тракт), `docs/02_settings_persistence_v1.0/` (`SP1.0`, хранение настроек), `docs/spec_visualizer_v5.1.md` (`V5.1`, визуализатор), `docs/spec_theme_v1.0.md` (`T1.0`, темы); при противоречии V5.1/T1.0 с AM1.0/SP1.0 действуют AM1.0/SP1.0. При противоречии спеки с любым другим документом, этим файлом или `architecture.md` действует спека. Навигация и таблица старый→новый путь — `docs/README.md`.
  - `docs/_template/` — шаблон и порядок работы для новой задачи (`process.md`, `prompt_template.md`).
  - `docs/acceptance/` — пакеты кросс-ОС приёмки для `tools/acceptance.py`.
  - `docs/_canceled/` — архив, не источник требований; читать ЗАПРЕЩЕНО без прямой просьбы пользователя (блокировано в `.claude/settings.json`). Старые коды в комментариях (`ТЗ A3.0 §7.3` и т. п.) — историческая пометка.
- `_DRAFTS_/` — личная папка пользователя: ЗАПРЕЩЕНО читать, открывать, изменять, перемещать её файлы и ссылаться на них. Игнорируй её существование.
- `_TODO_/history/` — архивы: закрытые спеки (`archive_<Префикс>.md`; прежние — `archive_v0.x.md`) и закрытые баги (`archive_bugs.md`). Других подкаталогов в `_TODO_/` нет, инбокса нет.
- `examples/` — справочные примеры, только чтение; мутировать и перезаписывать ЗАПРЕЩЕНО.

## Трассируемость

- ID задачи ROADMAP: `<Префикс>-8.<N>` — этап СN таблицы §8 спецификации, `<Префикс>-B<N>` — баг; префиксы — реестр в шапке `ROADMAP.md` (регистрация нового — `docs/_template/process.md`), правки процесса (`AGENTS.md`, `.claude/`, хуки, `tools/`, `docs/00_workflow_v1.0/`) — `WF1.0`. ID, якоря столбца «ТЗ» и маркеры статуса проверяет `python tools/traceability_tool.py check` (из `hooks/pre-commit`); формат строки и якоря — `task_intake.md` §4.
- Новый и переписываемый код ссылается в doc-комментариях на `ТЗ-N` / `ADR-N` / `§X.Y` действующей спеки; какая спека у файла и когда ссылке нужен префикс (`SP1.0 ТЗ-8`) — `architecture.md` §3.1. Коды `A2.0`/`A3.0`/`AP5.0` в новый код не добавляются, старые пометки удаляются вместе с заменяемым кодом. Проверяется ревью.
- Цепочка связей: ревью (R-N) → ТЗ (ТЗ-N, ОВ-N) → спека (ADR-N, §, этап СN) → строка `ROADMAP.md` (ID) → шаг `_STATE_.yaml` → код (doc-комментарии) → коммит `(<ID>, step <N>)` → `✅ сделано в <hash>` → архив `_TODO_/history/`.
- Из спеки читай по ссылке только нужный раздел, не весь документ.

## Процедуры — где что читать

Процедуры живут в `docs/00_workflow_v1.0/` и читаются по ссылке, когда до них доходит дело — не держи их в контексте заранее:

| Файл | Когда читать | Содержание |
|---|---|---|
| `planning.md` | старт каждой сессии | режимы Продолжение/Новая задача, проверка репозитория, выбор задачи, что читать из спеки, микро-декомпозиция, запись в `_STATE_.yaml`, регистрационный коммит и подтверждение плана |
| `task_intake.md` | задача пришла из чата | два пути (в рамках спеки / полный цикл), префикс и номер, приоритет, формат B-строки, закреплённый в документации текст |
| `execution.md` | каждый микро-шаг | вайтлист, правка, верификация, успех/провал (3/3), исполнители, остановка для очистки контекста, `hooks/pre-commit` |
| `closing.md` | все шаги `done: true` | закрытие этапа или бага: ROADMAP, ручные проверки, заметка плана, консервация `_STATE_.yaml`, коммит, отчёт |
| `spec_closing.md` | закрыт последний этап спецификации | открытые баги спеки, кросс-ОС приёмка, архив-паспорт, строка статуса в ROADMAP |
| `architecture.md` | справочно | проект, команды, карта исходников, каталог → спека, Slint↔Rust, тесты, зависимости, запуск |
| `docs/_template/process.md` | новая фича / крупная доработка | промт → ревью → ТЗ → спецификация → решения → этапы в `ROADMAP.md` |

## Любая правка регистрируется

Лёгкого пути нет: опечатка, константа, однострочный баг, правка конфига или процесса — тоже строка `<Префикс>-B<N>` в `ROADMAP.md` и сессия в `_STATE_.yaml` (для мелочи — один шаг). Задача из чата регистрируется по `task_intake.md`; этап спецификации берётся по `planning.md` §3.

Дефект вне текущей задачи, найденный по ходу работы, не чини молча: добавь B-строку со статусом `⬜ открыто` (без сессии; формат — `task_intake.md` §4) и продолжай свою задачу.

Без B-строки и сессии делаются только служебные коммиты, не меняющие код и текст `docs/`: подтверждение или отказ от ручной проверки (`chore(state): manual check <ID> confirmed|waived <дата>`, `closing.md` §2) и результаты кросс-ОС приёмки, которые записывает и коммитит `tools/acceptance.py run` (сообщение формирует инструмент: `acceptance(<пакет>): <ОС> <вердикт> @ <hash>`).

## Жёсткие правила кода

У каждого правила указан проверяющий инструмент; «проверяется ревью» — инструмента нет.

- **Нет `unwrap()`/`expect()`/`unreachable!()` вне тестов.** Запрещены `[lints.clippy]` в `Cargo.toml` (`unwrap_used`, `expect_used`, `unreachable = "deny"`); допускаются в `#[test]`/`#[cfg(test)]` (`clippy.toml`). Проверяет `cargo clippy`.
- **Нет прямой зависимости от бэкендов (ALSA/WASAPI/ASIO).** Взаимодействие с оборудованием — только через трейты (`AudioHost` в `src/audio/output.rs`, `AudioSource` в `src/audio/decoder.rs`). Проверяется ревью.
- **0 аллокаций, без блокировок, логирования и I/O в аудио-колбэке.** Запрещены `Mutex`/`RwLock`/`Condvar`, `log::`/`tracing::`, `println!`/`eprintln!`, `std::fs`/`std::io`, `Box::new`/`Vec::`/`vec!`/`String`. В `src/audio/render/**` проверяет `python tools/check_rt_imports.py` (вызывается из `hooks/pre-commit`); вне этого каталога (другие горячие циклы DSP) — проверяется ревью.
- **TPDF-дизеринг и прочий шум в колбэке — через быстрый безалокационный ГПСЧ** (LCG/LFSR/LUT), не `rand::thread_rng()`. Проверяется ревью (не ловится `check_rt_imports.py`).
- **Нет `as` при масштабировании сэмплов/смене разрядности.** Используй `.clamp()`, `try_into()`, `from_sample()`. Проверяется ревью (`clippy::as_conversions` в проекте не включён).
- **Нет `.clone()` тяжёлых объектов (`Track`, `Vec`, `Settings`) ради обхода времени жизни.** Передавай по `&`; разделяемые ресурсы — атомики/`Arc<Mutex>`/`Arc<RwLock>` только на границах потоков. Проверяется ревью.
- **Мутируемое состояние `MusicApp` — в `src/app/mod.rs` и вью-структурах подмодулей `src/app/*`**, расширяется через `impl MusicApp`, общение — `pub(super)`. Проверяется ревью.
