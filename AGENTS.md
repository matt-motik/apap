# AGENTS.md

> СТРОГОЕ ПРАВИЛО НАЧАЛА СЕССИИ: Первым действием всегда делай `git pull`, затем читай `_STATE_.yaml` (не `_STATE_.md` — это сгенерированное представление для человека с тем же содержимым).
> Если в `_STATE_.yaml` `status: in_progress` -> переходи в режим "Продолжение" (открытая сессия доводится до закрытия первой).
> Если состояние `done` или файл отсутствует -> переходи в режим "Новая задача".
> Если в поле `plan:` `_STATE_.yaml` есть пункт со `status: in_progress` (в `_STATE_.md` — `[>]`) -> это текущая работа пользователя: сообщи о ней; когда открытой сессии нет — её следующий этап и есть задача сессии (`planning.md` §3).
> На каждом переходе шага объявляй в чате, какой шаг завершён и какой текущий (после `render`).

## Продукт и приоритеты

APAP — аудиофильский плеер (Rust + Slint). Когда спека не даёт ответа (выбор решения, приоритет бага), порядок такой:

1. **Честность сигнала** — плеер никогда не заявляет bit-perfect, если это не так, и не меняет сигнал молча.
2. **Безопасность слуха и оборудования** — скачок громкости, DoP на ЦАП без DoP, полная шкала → баг 🔴.
3. **Надёжность реального времени** — без дропаутов и заиканий.
4. **Удобство** интерфейса.

При сомнении выбирай вариант, сохраняющий сигнал, и спрашивай пользователя. Платформы: Linux (ALSA, PipeWire), Windows (WASAPI, ASIO), macOS (CoreAudio). Ветки `cfg` другой ОС локально не компилируются — их проверяет ревью, а сборка на другой машине записывается в `note` пункта плана.

## Артефакты и правила доступа к ним

Нарушение правил доступа к артефактам — критическая ошибка:

- `_STATE_.yaml` — состояние текущей сессии, единственная точка входа: читаешь и правишь только его (схема — `tools/schema/state.schema.json`). Другие файлы состояния (`plan-*.md`, `.current-plan.json`) создавать запрещено. `_STATE_.md` генерируется командой `python tools/state_tool.py render`, ручная правка `.md` блокируется pre-commit; агент его не читает. Многошаговый план поверх задач — поле `plan:`.
- Пользователь работает на двух машинах; между ними переносится **только git** (`_STATE_.yaml`, `ROADMAP.md`, `docs/`). Память агента и задачи сессии не переносятся.
- `ROADMAP.md` — единый технический бэклог; задачи = этапы спецификаций (см. «Документация и трассируемость» ниже). Изменяется точечно (patch/diff), не затирая соседние строки, и строго по согласованию с `_STATE_.yaml`. Порядок этапов **внутри одной спецификации** менять запрещено; порядок **между несколькими спецификациями** может быть переопределён разделом «Сквозной порядок этапов» в `ROADMAP.md`.
- `docs/` — действующая документация, папки `docs/NN_имя_vX.Y/`. Изменяется ТОЛЬКО по явному разрешению пользователя. Действующие спеки продукта: `docs/01_audio_modes_v1.0/` (`AM1.0`, аудио-тракт), `docs/02_settings_persistence_v1.0/` (`SP1.0`, хранение настроек), а для визуализатора и тем — `docs/spec_visualizer_v5.1.md` (`V5.1`) и `docs/spec_theme_v1.0.md` (`T1.0`); при противоречии V5.1/T1.0 с AM1.0/SP1.0 действуют AM1.0/SP1.0. При противоречии между спекой и любым другим документом или разделом «Жёсткие правила кода» ниже — действует спека. Навигация и таблица старый→новый путь — `docs/README.md`.
  - `docs/_template/` — шаблон и порядок работы для новой задачи (`process.md`, `prompt_template.md`).
  - `docs/acceptance/` — пакеты кросс-ОС приёмки для `tools/acceptance.py`.
  - `docs/_canceled/` — архив, не источник требований. ТЕБЕ ЗАПРЕЩЕНО читать этот каталог без прямой просьбы пользователя (блокировано в `.claude/settings.json`). Старые коды в комментариях (`ТЗ A3.0 §7.3` и т. п.) — историческая пометка, таблица соответствия — `docs/README.md`.
- `_DRAFTS_/` — личная папка пользователя. ТЕБЕ ЗАПРЕЩЕНО читать, открывать, изменять, перемещать файлы из неё или ссылаться на них. Игнорируй её существование.
- `_TODO_/history/` — архивы: закрытые спеки (`archive_<Префикс>.md`; прежние — `archive_v0.x.md`) и закрытые баги (`archive_bugs.md`). Других подкаталогов в `_TODO_/` нет, инбокса нет.
- `examples/` — справочные примеры. ТЕБЕ ЗАПРЕЩЕНО мутировать/перезаписывать файлы в этом каталоге. Доступ только на чтение.

## Документация и трассируемость

- Префикс спецификации объявляется в шапке её `03_spec.md` и регистрируется в реестре шапки `ROADMAP.md` (уникален, проверяет `python tools/traceability_tool.py check`). Правки вне спек продукта (`AGENTS.md`, `.claude/`, хуки, `tools/`) регистрируются под префиксом `WF1.0` (якорь — `docs/00_workflow_v1.0/README.md`).
- ID задачи ROADMAP: `<Префикс>-<§>.<N>`; этапы внедрения — `<Префикс>-8.<N>` = этап СN таблицы §8 спецификации; баги — `<Префикс>-B<N>`.
- Ссылка в столбце «ТЗ» — на якорь раздела спецификации, GitHub-стиль (нижний регистр, пунктуация удаляется, пробелы → `-`): `[§8 С0](docs/01_audio_modes_v1.0/03_spec.md#8-этапы-внедрения)`.
- Новый и переписываемый код ссылается на `ТЗ-N` / `ADR-N` / `§X.Y` действующей спецификации в doc-комментариях. Номера у спек пересекаются: ссылка без префикса относится к спеке модуля, на чужую спеку и в смешанных файлах — с префиксом (`SP1.0 ТЗ-8`); таблица «каталог → спека» — `architecture.md` §3.1. Коды `A2.0`/`A3.0`/`AP5.0` в новый код не добавляются, старые пометки удаляются вместе с заменяемым кодом. Проверяется ревью.
- Экономия контекста: по ссылке читай только нужный раздел спеки, не весь документ.
- Цепочка связей: ревью (R-N) → ТЗ (ТЗ-N, ОВ-N) → спека (ADR-N, §, этап СN) → строка `ROADMAP.md` (ID) → шаг `_STATE_.yaml` (ТЗ/§ в описании) → код (ссылки в doc-комментариях) → коммит (`(<ID>, step <N>)`) → `✅ сделано в <hash>` → архив `_TODO_/history/`.
- Перенос выполненных этапов в `_TODO_/history/archive_<Префикс>.md` — технический паспорт решения (коммит, дата, формулы, структуры данных, размеры буферов/FFT, RT-константы), процедура — `closing.md` §5.

## Процедуры — где что читать

Полные процедуры живут в `docs/00_workflow_v1.0/` и читаются по ссылке, когда до них доходит дело — не держи их в контексте заранее:

| Файл | Когда читать | Содержание |
|---|---|---|
| `task_intake.md` | задача пришла из чата | регистрация без кода, баг vs новая фича, приоритеты, формат B-строки, закреплённый в документации текст |
| `planning.md` | старт сессии, выбор/декомпозиция задачи | режимы Продолжение/Новая задача, аудит репозитория, что читать из спеки, микро-декомпозиция, запись в `_STATE_.yaml` |
| `execution.md` | каждый микро-шаг | вайтлист, правка, верификация, успех/провал, делегирование субагентам, остановка для очистки контекста, `hooks/pre-commit` |
| `closing.md` | все шаги `done: true`, закрытие сессии/этапа | статус в ROADMAP, общие условия §8, ручные проверки, консервация `_STATE_.yaml`, итоговый отчёт |
| `architecture.md` | справочно, не при каждой сессии | проект, команды верификации, карта исходников, связка Slint↔Rust, тесты, зависимости, запуск |
| `docs/_template/process.md` | новая фича/крупная доработка | промт → ревью → ТЗ → спецификация → решения → этапы в `ROADMAP.md` |

## Любая правка регистрируется

Лёгкого пути без регистрации нет: опечатка, константа, однострочный баг, правка конфига — тоже строка `<Префикс>-B<N>` в `ROADMAP.md` и сессия в `_STATE_.yaml` (для мелочи сессия — один шаг). Классификация задачи, приоритеты и формат строки — `task_intake.md`.

Без B-строки и сессии делаются только служебные коммиты, не меняющие код и текст `docs/`: подтверждение или отказ от ручной проверки (`chore(state): manual check <ID> confirmed|waived <дата>`, `closing.md` §3) и результаты прогона кросс-ОС приёмки, записанные `tools/acceptance.py` (`chore(acceptance): <пакет> <ОС> <дата>`, `closing.md` §5).

## Делегирование

Новый субагент с чистым контекстом на каждый микро-шаг; продолжать того же агента — только в пределах одного шага. Остановка для очистки контекста (с пользовательским тогглом на сессию) и правило моста при смене типа >2–3 файлов — `execution.md` §6–7.

## Жёсткие правила кода

Действуют, пока не противоречат действующим спекам (`docs/01_audio_modes_v1.0/`, `docs/02_settings_persistence_v1.0/`) — при противоречии действует спека. У каждого правила — проверяющий инструмент, где он есть; иначе явно указано «проверяется ревью».

- **Нет `unwrap()`/`expect()`/`unreachable!()` вне тестов.** Запрещены `[lints.clippy]` в `Cargo.toml` (`unwrap_used`, `expect_used`, `unreachable = "deny"`); допускаются в `#[test]`/`#[cfg(test)]` (`clippy.toml`). Проверяет `cargo clippy`.
- **Нет прямой зависимости от бэкендов (ALSA/WASAPI/ASIO).** Взаимодействие с оборудованием — только через трейты (`AudioHost` в `src/audio/output.rs`, `AudioSource` в `src/audio/decoder.rs`). Проверяется ревью.
- **0 аллокаций, без блокировок, логирования и I/O в аудио-колбэке.** Запрещены `Mutex`/`RwLock`/`Condvar`, `log::`/`tracing::`, `println!`/`eprintln!`, `std::fs`/`std::io`, `Box::new`/`Vec::`/`vec!`/`String`. В `src/audio/render/**` проверяет `python tools/check_rt_imports.py`, вызывается из `hooks/pre-commit`; вне этого каталога (другие горячие циклы DSP) — проверяется ревью.
- **TPDF-дизеринг и прочий шум в колбэке — через быстрый безалокационный ГПСЧ** (LCG/LFSR/LUT), не `rand::thread_rng()`. Проверяется ревью (не ловится `check_rt_imports.py`).
- **Нет `as` при масштабировании сэмплов/смене разрядности.** Используй `.clamp()`, `try_into()`, `from_sample()`. Проверяется ревью (`clippy::as_conversions` в проекте не включён).
- **Нет `.clone()` тяжёлых объектов (`Track`, `Vec`, `Settings`) ради обхода времени жизни.** Передавай по `&`; разделяемые ресурсы — атомики/`Arc<Mutex>`/`Arc<RwLock>` только на границах потоков. Проверяется ревью.
- **Мутируемое состояние `MusicApp` — в `src/app/mod.rs` и вью-структурах подмодулей `src/app/*`**, расширяется через `impl MusicApp`, общение — `pub(super)`. Проверяется ревью.
