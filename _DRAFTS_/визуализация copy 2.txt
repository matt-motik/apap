# ТЗ: Визуализация аудио в плеере на Rust + Slint (v5.0)

## 1. Общие положения

### 1.1. Назначение
Добавить в музыкальный плеер (Rust + Slint) подсистему визуализации с тремя режимами, независимыми настройками для каждого и поддержкой стерео/моно. Визуализация должна отображать сигнал **WYSIWYG** (What You See Is What You Get) — тот самый цифровой поток, который физически отправляется в драйвер звуковой карты.

### 1.2. Область
- Крейт/модуль: `audio::visualizer` (обработка) + `ui::visualizer` (Slint-компонент).
- Интеграция с `audio::player` (PlaybackCore, cpal callback) и `audio::decoder` (`Decoder`, `DsdDecoder`).
- **Архитектурное решение:** Доработка существующего `DsdDecoder` для поддержки потоковой децимации и изменения битности. Создание нового декодера не требуется.
- UI настроек — отдельная вкладка.
- Персистентность через `serde` + TOML в `~/.config/<app>/config.toml`.

### 1.3. Термины
| Термин | Значение |
|---|---|
| Полнотрековая визуализация | Строится один раз по всему треку (или его конвертированной версии), кэшируется как изображение. |
| Мгновенная визуализация | Обновляется непрерывно во время воспроизведения на основе реального аудиопотока. |
| WYSIWYG | Принцип: визуализация соответствует сигналу на выходе ЦАП. |
| Потоковая децимация | Процесс понижения частоты дискретизации DSD "на лету" блоками, без загрузки всего файла в память. |
| Bit-perfect | Режим вывода без ресемплинга, софтверной громкости и конвертации форматов. |
| Native DSD | Вывод 1-битного DSD-потока на ЦАП напрямую. |
| DoP | DSD over PCM: DSD-биты в PCM-контейнере. |

## 2. Архитектура

### 2.1. Два класса визуализаций

| Класс | Режимы | Источник данных | Когда строится |
|---|---|---|---|
| **Полнотрековый** | Осциллограмма, Спектрограмма | Отдельный поток: повторное открытие файла через `DsdDecoder`/`Decoder` с теми же настройками конвертации. | Один раз при загрузке трека (если не отключено), в фоне. Кэшируется как изображение. |
| **Мгновенный** | Анализатор спектра | `cpal` callback (tap PCM-потока перед отправкой в устройство). | Непрерывно во время игры. |
| — | Отключено | — | — |

### 2.2. Компоненты

```
                            ┌────────────────────────┐
                            │      UI (Slint)        │
                            └────┬──────────────▲────┘
                                 │ команды      │ кадры
                                 ▼              │
        ┌──────────────────────────────┐  ┌──────────────────┐
        │  FullTrackWorker             │  │  LiveWorker      │
        │  (Фоновый поток)             │  │  (UI поток /     │
        │  Открывает файл заново       │  │   таймер)        │
        │  Decoder/DsdDecoder →        │  │                  │
        │  image (SharedPixelBuffer)   │  │  Ring Buffer ←───┼── cpal callback
        └────────────┬─────────────────┘  │  (tap после DSP) │
                     │                    └────────▲─────────┘
                     │                             │
                     ▼                      PlaybackCore
              Кэш изображений               (Resampler / DsdDecoder)
              (LRU + диск)                        ↓
                                             Audio Device
```

### 2.3. Поток данных

**Полнотрековая (Осциллограмма/Спектрограмма):**
1. При старте трека (если режим активен и не пропущен для DSD): UI шлёт команду `Build { path, settings_snapshot }`.
2. `FullTrackWorker` (отдельный поток) открывает **новый экземпляр** декодера для этого файла.
   - **Важно:** Экземпляр использует **те же настройки** конвертации (Sample Rate, Bit Depth), что и основной плеер, чтобы обеспечить принцип WYSIWYG.
3. Декодер читает файл блоками (потоковая децимация для DSD), избегая перегрузки памяти.
4. Данные обрабатываются (min/max для осциллограммы, FFT для спектрограммы) и накапливаются в изображение.
5. Готовое изображение передаётся в UI через `slint::invoke_from_event_loop`.
6. UI рисует изображение, поверх него движется курсор позиции из `Player::snapshot()`.
7. Прогресс построения отображается в UI. Реализована возможность отмены (`AtomicBool`) при смене трека или настроек.

**Мгновенная (Анализатор спектра):**
1. В `audio_callback` основного потока воспроизведения, **после** всех преобразований (ресемплинг, громкость, DSD→PCM), но **до** записи в буфер устройства, данные копируются в lock-free ring buffer (`rtrb`).
2. Копирование происходит **только** если активен режим анализатора.
3. `LiveWorker` (в UI потоке или отдельном) читает буфер, выполняет FFT, формирует полосы.
4. Полосы передаются в Slint-компонент для отрисовки.

### 2.4. Ключевые требования к архитектуре
- **Аудио-callback никогда не блокируется:** `try_push` в ring buffer; при переполнении — дроп старых данных.
- **Отсутствие аллокаций в горячем цикле:** Переиспользуемые буферы в callback и worker'ах.
- **Потокобезопасность UI:** Все обновления свойств Slint из рабочих потоков выполняются строго через `slint::invoke_from_event_loop`.
- **WYSIWYG:** Параметры конвертации DSD→PCM для полнотрековой визуализации должны строго совпадать с параметрами воспроизведения.
- **Изоляция потоков:** `FullTrackWorker` не влияет на производительность воспроизведения (не делит ресурсы CPU в реальном времени).
- **Debounce:** При изменении настроек визуализации во время построения, текущее задание отменяется, и новое запускается с задержкой (debounce ~500мс).

- При смене — worker пересчитывает/перестраивает буфер.

## 6. Обработка DSD

### 6.1. Классификация режимов DSD

| Режим | Вывод на ЦАП | Визуализация |
|---|---|---|
| **DSD → PCM** (обычная звуковая карта) | PCM после `DsdDecoder` (с настройками target_sr/bit) | **Работает** (WYSIWYG, по конвертированному потоку) |
| **DSD native** | 1-битный DSD-поток напрямую | **Отключена**, плейсхолдер «Недоступно в Native DSD» |
| **DoP** | DSD-биты в PCM-контейнере | **Отключена**, плейсхолдер «Недоступно в DoP режиме» |

### 6.2. DSD → PCM: Визуализация и архитектура
- **Декодер:** Существующий `DsdDecoder` дорабатывается для поддержки параметров `target_sample_rate` и `target_bit_depth`. Конвертация происходит потоково (блоками) с децимацией, что исключает переполнение памяти даже для DSD512.
- **Полнотрековая визуализация:**
  - Используется **второй экземпляр** `DsdDecoder` в фоновом потоке (`FullTrackWorker`).
  - Он открывает файл заново и применяет **те же настройки конвертации**, что и основной плеер.
  - Результат (изображение) кэшируется. Аудио-файл на диске не создается.
  - **Оптимизация:** Добавлена настройка `skip_fulltrack_for_dsd` (по умолчанию `true`). Если включена, полнотрековая визуализация для DSD-файлов не строится (показывается только мгновенный спектр или плейсхолдер), чтобы избежать долгого ожидания перед стартом.
- **Мгновенная визуализация:** Работает стандартно через tap потока после конвертации.

### 6.3. DSD native / DoP: Визуализация отключена
При активном native/DoP-режиме вывода:
- Все три визуализации недоступны.
- Отображается специфический плейсхолдер с сообщением о причине («Визуализация недоступна в Native DSD / DoP режиме»).
- Переключение типа визуализации не приводит к запуску обработки.
- `FullTrackWorker` и `LiveWorker` не запускаются.

## 7. Bit-perfect режим

### 7.1. Определение
`audio.bit_perfect = true` — вывод без ресемплинга, без софтверной громкости, без конвертации форматов.

### 7.2. Влияние на громкость
- Громкость регулируется внешним предусилителем или на уровне ОС.
- Слайдер громкости в UI заблокирован, подпись: «Управляется внешним устройством / ОС».
- Mute отключён.

### 7.3. Влияние на визуализацию
- **PCM:** Визуализация работает (tap до выхода). Bit-perfect сохраняется.
- **DSD → PCM:** Конвертация DSD в PCM технически нарушает bit-perfect исходного файла.
  - Поведение: Визуализация работает.
  - UI: Показывать **информативное предупреждение** (не блокирующее): «Режим DSD→PCM активен. Bit-perfect исходного потока не гарантируется».
  - Индикатор «Bit-perfect» в статус-баре может мигать или менять цвет, сигнализируя о конвертации.
- **DSD Native/DoP:** Визуализация отключена (см. §6.3).

## 8. Настройки DSD → PCM (Интеграция в DsdDecoder)

### 8.1. Назначение
Управление конвертацией DSD в PCM внутри `DsdDecoder` для вывода на обычную звуковую карту.

### 8.2. Расположение
Отдельная вкладка **«DSD»** в диалоге настроек.

### 8.3. Поля
| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `dsd.mode` | enum | `pcm` | `pcm` (конвертация) / `native` / `dop` |
| `dsd.target_sample_rate` | enum | `auto` | auto / 44100 / 48000 / 88200 / 96000 / 176400 / 192000 |
| `dsd.target_bit_depth` | enum | `24` | 16 / 24 / 32 (integer) / 32 (float) |
| `dsd.resampler_algorithm` | enum | `sinc_medium` | linear / cubic / sinc_fast / sinc_medium / sinc_slow |
| `dsd.dither_enabled` | bool | `true` | Дизеринг при понижении битности |
| `dsd.dither_type` | enum | `tpdf` | tpdf / triangular / off |

*Примечание: Параметры фильтрации (CIC order, cutoff) являются внутренними и фиксированными для обеспечения стабильности, так как определяются архитектурой децимации.*

### 8.4. Алгоритмы ресемплирования
Реализуются внутри `DsdDecoder` или вызываемого им модуля ресемплинга.
- `linear`, `cubic`: Базовые, низкая нагрузка.
- `sinc_*`: Высокое качество, средняя/высокая нагрузка.
- `soxr_*`: (Опционально, Этап 2) Требует внешней зависимости `libsoxr`.

### 8.5. Взаимодействие с bit-perfect
- При `bit_perfect = true` и выборе режима `pcm`:
  - Показывать предупреждение о несовместимости конвертации с концепцией bit-perfect источника.
  - Пользователь может продолжить работу в режиме конвертации.

## 11. Производительность и Ресурсы

### 11.1. Бюджеты

**Полнотрековые (FullTrackWorker):**
| Параметр | Значение |
|---|---|
| Построение осциллограммы (5 мин PCM) | ≤ 1 с |
| Построение спектрограммы (5 мин PCM) | ≤ 2 с |
| Построение DSD64→PCM (5 мин) | ≤ 3 с |
| Построение DSD512→PCM (5 мин) | ≤ 30 с (SSD) / ≤ 180 с (HDD) |
| CPU нагрузка (пик построения) | ≤ 1 ядра (100%) |
| Peak RAM при построении | ≤ 128 МБ |

**Мгновенные (LiveWorker + Callback):**
| Параметр | Значение |
|---|---|
| Задержка отрисовки | ≤ 50 мс |
| Частота обновления UI | 30–60 FPS |
| Нагрузка FFT (LiveWorker) | ≤ 5% одного ядра |
| Нагрузка Callback (tap + copy) | Минимальная (< 1%) |
| Аллокации в горячем цикле | 0 |

### 11.2. Оптимизации
- FFT — `rustfft` с предвычисленным планом.
- Ring buffer — `rtrb` (lock-free).
- Потоковая обработка DSD без загрузки всего файла в память.
- Кэш изображений — LRU на N треков + диск.

## 12. Отказоустойчивость

| Ситуация | Поведение |
|---|---|
| Ring buffer переполнен | Дроп старых сэмплов |
| Ошибка построения FullTrack | Плейсхолдер + лог warning |
| Некорректные настройки | Откат к предыдущим валидным |
| DSD native / DoP | Плейсхолдер «Недоступно» |
| Bit-perfect + DSD→PCM | Информативное предупреждение |
| Seek во время Build | Курсор двигается, Build продолжается (или отменяется при новом seek) |
| Смена настроек во время Build | Cancel текущего + Debounce + Restart |

## 13. Взаимодействие с плеером

### 13.1. Сигналы
- `TrackChanged`: Запуск FullTrackWorker (если не пропущено).
- `StateChanged`: Пауза/стоп обновлений LiveWorker.
- `PositionChanged`: Движение курсора.
- `SettingsChanged`: Перезапуск workers при необходимости.

### 13.2. Приоритет плейсхолдеров
1. Если режим `off` → Базовый плейсхолдер (Артист/Альбом).
2. Если режим активен, но файл DSD Native/DoP → Плейсхолдер «Недоступно в Native/DoP».
3. Иначе → Визуализация.

## 14. UI-компонент (Slint)

### 14.1. Компонент `Visualizer`

2. Осталось исправить (существенное)
2.1. §2.2 / §2.3: LiveWorker — в UI-потоке или отдельном?

Противоречие:

    Диаграмма §2.2: LiveWorker (UI поток / таймер).

    §2.3: LiveWorker (в UI потоке или отдельном) читает буфер.

Проблема: FFT 2048/8192 на UI-потоке при 60 FPS даст заметный jank (замерший UI, пропущенные кадры отрисовки). Это уже было явно решено в v3/v4: отдельный поток.

Правка: зафиксировать — LiveWorker работает в отдельном потоке. UI-поток только получает готовые бары через slint::invoke_from_event_loop и обновляет модель. Таймер UI (slint::Timer) может использоваться как «тиканье» для перерисовки, но FFT — вне UI-потока.
2.2. §2.2 / §2.4: DeviceChanged не описан

DeviceChanged — важное событие. Что происходит:

    PlaybackCore пересоздаётся, Player::open перезапускает трек.

    LiveWorker читает ring buffer, который сбрасывается → возможны «старые» бары.

    FullTrackWorker работает с файлом, не с устройством → не должен прерываться.

    Но: при смене target_sample_rate в DSD→PCM (или при выборе другого устройства с другой частотой) — параметры конвертации для WYSIWYG меняются → FullTrackWorker должен перестроиться.

Правка: добавить в §12 строку:

    DeviceChanged: LiveWorker сбрасывает ring buffer. FullTrackWorker перезапускается только если сменились параметры конвертации DSD→PCM (target_sr, target_bit_depth, resampler); иначе продолжает работу.

2.3. §9.3 / §10: нет формулы ключа кэша

Не описано, как формируется ключ, по которому определяется, что кэш валиден.

Правка: добавить в §10 (или §9.3):

    Ключ кэша: hash(path + mtime + size + mode + channels + params_snapshot), где params_snapshot включает все параметры соответствующего типа визуализации (fft_size, palette, freq_scale, freq_min/max, gain_db, range_db, high_boost, dsd_cic_compensation) и параметры конвертации DSD (target_sr, target_bit_depth, resampler_algorithm), если трек DSD.

    При смене любого из этих параметров — старая запись инвалидируется, строится новая.

    cache_ttl_days — по mtime файла: если исходный файл новее кэша, кэш инвалидируется.

2.4. §11.1: нет общего лимита RAM-кэша

В v4.0 было «≤ 64 МБ суммарно». В v5.0 остался только per-build лимит (≤ 128 МБ) и per-worker. Нужен явный общий лимит RAM для кэша изображений, иначе LRU будет расти неограниченно.

Правка: добавить:

    Общий лимит RAM-кэша изображений (все треки): ≤ 64 МБ. При превышении — LRU-вытеснение старых треков. Per-track лимит — производная.

3. Мелочи (можно править по ходу)
3.1. §8.3: resampler_algorithm живёт в dsd.*, но применяется и к PCM

Ресемплер нужен не только для DSD→PCM. Например: FLAC 96 кГц на устройстве 44.1 кГц — тоже ресемплинг. Если пользователь хочет выбрать sinc_slow для всего, а не только для DSD, настройка в dsd.* — неудачное место.

Правка (опционально): вынести resampler_algorithm в [audio.resampler] с пометкой «применяется ко всем трекам, где требуется ресемплинг, включая DSD→PCM». Если решено оставить в dsd.* — добавить примечание, что для PCM-треков ресемплер выбирается автоматически.
3.2. §10: нет примера TOML

В v4.0 был. Стоит вернуть — облегчает ревью и реализацию.
3.3. §15: нет теста корректности DSD→PCM

Есть «нет переполнения памяти при DSD512», но нет «PCM не содержит NaN, не тишина, peak в разумных пределах». Юнит-тест DsdDecoder в коде уже это делает (decode_second), стоит упомянуть в критериях приёмки.

Не отражено, что ресемплер (linear/cubic/sinc_*) — тоже часть этапа 3. Может быть, добавить в название этапа: «Доработка DsdDecoder + ресемплеры».

Не сказано, показывать ли артиста/альбом/формат всегда или только когда трек загружен. При пустом плейлисте — что показывать?
